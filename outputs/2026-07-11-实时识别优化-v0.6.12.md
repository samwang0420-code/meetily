## 2026-07-11 · 离线会记 实时语音识别优化 v0.6.12 (streaming 接入 + 延迟埋点)

**用户反馈**: "豆包能力实时识别字幕比我们现在强了几百倍"

**根因诊断 (本轮发现)**:
- 项目以前声称支持"实时 streaming partial" (`transcript-partial` 事件 + `livePartialText`), **但实际后端从未接入**!
  - `frontend/src-tauri/scripts/sherpa_asr.py` 有完整的 `stream_begin/chunk/finalize` 实现
  - `frontend/src-tauri/src/audio/sherpa_daemon.rs` 暴露 `stream_*` 方法 + tauri command `sherpa_stream_*`
  - **但** `frontend/src-tauri/src/audio/transcription/worker.rs` 完全没调 streaming 路径
  - `TranscriptionEngine::Sherpa` unit variant 不携带任何能力, 实际跑会 skip + 走 fallback Whisper 路径
  - `_sqlx_migrations`、`worker.rs.bak` 等备份文件里有老 streaming 代码, 表明历史有这功能但被回滚了
- 用户感知"差几百倍"真实原因:
  1. 整段 `transcribe_blocking` (一次性 base64 + IPC + 离线 decode) 延 600ms-2s 出文字
  2. SenseVoice 模型本身是 NAR, 不支持 streaming 输出
  3. 无 LM 上下文解码, 中英混排/同音字纠错弱

**实现 v0.6.12 (4 项)**:

### P1. 真的接 streaming (核心)
- `sherpa_provider.rs`: 重写整个 `transcribe()` → 走 `sherpa_daemon.stream_chunk()`
- 维护 lazy long-lived streaming session (static `STREAM_SESSION_COUNTER` + `Mutex<Option<StreamingSession>>`)
- 每次 transcribe: stream_begin (首次) → stream_chunk → 返 (partial text, is_endpoint)
- partial 通过 `app.emit("transcript-partial", ...)` 推前端
- endpoint + delta: 返 final text 走 worker.rs 原 transcript-update 路径
- 同步 `sherpa_provider.rs::finalize_session()` (录音停止时调用)

### P2. 降 streaming 阈值 (感知延迟↓)
- `sherpa_asr.py`: `chunk_threshold_ms` 600→200 / `silence_threshold_ms` 1200→500
- 加 `min_partial_interval_ms=150` 防 decode 风暴
- `sherpa_daemon.rs` 同步默认值

### P3. 加 latency 埋点 (让用户看到延迟, 可观测)
- `sherpa_asr.py`: 返 `decode_ms` / `buffer_age_ms` / `elapsed_ms` (空 emit 也返)
- `sherpa_provider.rs`: emit `transcript-partial` payload 携带 `decode_ms` / `buffer_age_ms`
- `worker.rs`: 新增 `get_streaming_timing_stats` tauri command + 50 样本 ring buffer (`Mutex<[i64; 50]>`)
- 新事件 `transcript-timing` (每秒 1 次)
- slow decode (>200ms) 触发 warn 日志

### P4. 前端 UI 优化
- `transcriptService.ts`: decode_ms / buffer_age_ms 字段 + `getStreamingTimingStats()`
- `TranscriptContext.tsx`: 暴露 `lastDecodeMs` / `lastBufferAgeMs`
- `TranscriptView.tsx`: partial 行右下方加 `decode 95ms` chip + `buf 200ms` chip (颜色编码: <100ms 灰 / 100-200ms 黄 / >200ms 橙)
- 切句 setTimeout 50ms → 400ms (等 transcript-update 把 final 段先塞进 transcripts, 避免黑屏闪烁)
- `motion.div` `transition={{ duration: 0.15 }}` 渐变

### engine.rs 关键修复
- 旧代码 `sherpa_paraformer | sherpa_funasr_nano` 分支直接 `Ok(TranscriptionEngine::Sherpa)` (unit variant 无能力)
- 改成 `Ok(TranscriptionEngine::Provider(Arc::new(SherpaProvider::new(model, app))))` — 走 Provider trait
- worker.rs 同时加 `TranscriptionEngine::Sherpa => warn + return Err` 兜底 (防回归)
