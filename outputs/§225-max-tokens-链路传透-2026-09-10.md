# §225 max_tokens 链路传透 + DEFAULT 4096→1200 — "重复生成" 真根因

## 触发

用户 2026-09-10 报告"总是重复生成"。

**实测症状** (用户机器跑 meeting-c1299582):
- invoke_log 多次记录 (11:35→11:37 / 13:00→13:01 / 14:04 / 12:53)
- 每次 invoke 跑 32+ 分钟卡住
- llama-helper 进程跑了 ~32 分钟后消失
- summary_processes status 永远 PENDING / chunk_count=0
- result 是空,result_backup 是旧的 9261 字符 cache

**关键日志** (`llama-helper.log`):
```
📝 Tokenized prompt: 9385 tokens
🔄 Starting generation (max_tokens: 4096)        ← 4096,不是 §52 的 800!
```

## 真根因 (链路断了)

**调用链** (从 service.rs 到 llama-helper):

| 文件:行 | 状态 |
|---|---|
| `service.rs:737` `resolve_max_tokens_for_model("qwen2.5:3b", None)` | ✓ 算出 **1200** (§191 per-model) |
| `service.rs:743` `generate_meeting_summary(.., resolved_max_tokens, ..)` | ✓ 传 1200 |
| `processor.rs:946` `clamp_max_tokens(max_tokens)` | ✓ 保留 1200 |
| `processor.rs:1043` `generate_summary(.., max_tokens_owned, ..)` | ✓ 传 1200 |
| `llm_client.rs:166` `generate_summary_with_stream(.., max_tokens, ..)` | ✓ 收 1200 |
| `llm_client.rs:203` `generate_with_builtin_stream(.., stream_sink,)` | ❌ **没传 max_tokens** |
| `client.rs:225` `max_tokens: Some(models::DEFAULT_MAX_TOKENS)` | ❌ **写死 4096** |

**根因链 (3 跳)**:
1. `models.rs:428` `DEFAULT_MAX_TOKENS: i32 = 4096` (历史 §64 改成,§191 §52 都期望 800/1200,但这条没同步)
2. `client.rs:225` 直接读这个常量,完全没接收 max_tokens 参数
3. `generate_with_builtin_stream` 函数签名没 `max_tokens` 参数 → 链路 4 个上游传的值被丢弃

**为什么"重复生成"是表象**:
- max_tokens=4096 → 单 chunk 跑 `4096 / 7.44 tok/s = 9.2 min`
- 4 chunks × 9.2 min = 36.8 min 才会完成
- 用户看着 UI 永远 PENDING,以为"卡了"
- 反复点重新生成 → invoke_log 看到多次 invoke (11:35→11:37, 13:00→13:01)
- 每次 invoke 实际都跑了 32+ min,llama-helper 进程在 §194 timeout 3600s 之前消失

## 铁律 (任何 v0.X 演进适用)

1. **max_tokens 链路不能断** — service→processor→llm_client→builtin_stream 任何一环漏传都让 caller 值失效
2. **DEFAULT_MAX_TOKENS 必须跟 §191 per-model 一致** — 实际取值应该走 resolve_max_tokens_for_model,constant 是兜底
3. **链路写测试必须覆盖最终输出** — Request::Generate JSON 序列化时 caller 值必须在
4. **AGENTS.md §X 描述 ≠ 代码 commit** (§92 §56) — §191 写了 per-model resolution,但 §64 把常量从 1200 改到 4096,链路没同步
5. **不要用兜底常量掩盖参数缺失** — `Some(models::DEFAULT_MAX_TOKENS)` 在 max_tokens 不存在时是救命,但存在时应该是 fallback 不是写死
