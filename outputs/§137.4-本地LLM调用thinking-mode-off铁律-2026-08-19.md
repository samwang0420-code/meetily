# §137.4 本地 LLM 调用 thinking mode off 铁律 (2026-08-19)

**触发**: 用户 8/19 指令"调用本地模型都需要使用 thinking mode:off 的模式" — 防止 Qwen3.5 thinking mode 拖慢 topic extract / 摘要 / dossier rebuild 等所有本地 LLM 推理。

## 1. 现状审计

### 三个本地 LLM 入口

| 入口 | 调用 | thinking mode off 实现 |
|---|---|---|
| BuiltInAI (Qwen3.5 2B 走 llama-helper sidecar) | `summary_engine/client.rs::generate_with_builtin_stream` | `model_def.template = "qwen3.5_nonthinking"` + `QWEN35_NONTHINKING_TEMPLATE` 强制 assistant 跳过 think 块 |
| Ollama (`localhost:11434`) | `summary/llm_client.rs::generate_summary` (provider=Ollama) | `llm_client.rs:297` `"think": false` (json body 字段) |
| LiveQA + topic_graph + dossier rebuild | 调 `generate_summary(provider=Ollama)` | 自动经 llm_client.rs 路径, think:false 自动应用 |

### 3 个调用点都覆盖 ✓

- `topic_graph/mod.rs:413/728` — topic extract + dossier rebuild
- `live_qa/mod.rs:129` — ⌥+Space 实时 Q&A

**实际已对**, 只是没有 guard 防未来漏掉。

## 3. 铁律 (适用所有未来 v0.X)

1. **Ollama provider 必须 `think:false`** — Qwen3.5 thinking mode 默认开, 推理 30-50s 且空 content
2. **BuiltInAI Qwen3.5 必须用 `qwen3.5_nonthinking` template** — 模板末尾 `<think>\n</think>\n\n` 强制跳过
3. **新加 LLM provider 必须立刻加 anchor** — 不加 anchor 下次重构被覆盖 (§56 §92 教训)
4. **不允许暴露"thinking mode"开关给用户** — 99% 用户不知道 Qwen thinking, 99% 场景不该用
5. **新加 model definition 必须配 nonthinking template** — 不允许只配 `qwen3.5` 默认 thinking template

## 4. 未来加新 LLM provider / model 的 SOP

1. 在 `models.rs` 加 `ModelDef`, template 字段必须指向 "nonthinking" 变体
2. 或:在 `llm_client.rs` 加 provider 分支, Ollama 路径加 `think:false`
3. 加 anchor 到 `check_historical_fixes.py`:
   - "thinking mode off" 字符串在该 provider/model 路径
   - 默认 template 是 "nonthinking" 变体
4. 跑 `python3 scripts/check_historical_fixes.py` 确认新增 anchor PASS
