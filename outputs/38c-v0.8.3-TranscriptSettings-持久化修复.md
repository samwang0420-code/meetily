# v0.8.3 §38 续 TranscriptSettings 切换持久化 (2026-07-31)

## 触发
用户原话: "我选择备选模型 为什么不能保存呢, 切换到别的地方又默认回来高精度模型了"

## 根因 (2 处)

### 1. TranscriptSettings.tsx 从未调 save
- provider onValueChange 只 setUiProvider, 不 setTranscriptModelConfig, 不 invoke save
- model onValueChange 只 setTranscriptModelConfig (React state), 不 invoke save
- React state 在 navigation/reload 后丢失
- 后端 `api_save_transcript_config` 命令完全存在, Sidebar/ParakeetModelManager 都调, 但**本组件缺这一段**

### 2. ConfigContext 强升 'paraformer-zh' → 'funasr-nano-zh'
- v0.8.3 commit 3104d82 把 'paraformer-zh' 加到 is_legacy_model
- 启动时: `is_legacy_model ? 'funasr-nano-zh' : config.model`
- 即使用户从前端切到 Paraformer-zh, 下次启动 ConfigContext 又把 model 改成 funasr-nano-zh
- 用户看到: "切到别的地方又默认回来高精度模型了"

## 修复 (commit 34d01fb)

### TranscriptSettings.tsx
新增 `saveTranscriptConfig(provider, model, apiKey)` helper (复刻 Sidebar 模板):
```ts
const saveTranscriptConfig = async (provider, model, apiKeyVal) => {
  try {
    const session = window.localStorage.getItem('lixianhuiji.session');
    await invoke('api_save_transcript_config', {
      provider, model, apiKey: apiKeyVal ?? null, session,
    });
  } catch (err) {
    console.error(err);
    safeToast.error('保存失败, 请重试');
  }
};
```

调用点:
- provider onValueChange: 推导新 default model (sherpa_paraformer → 'paraformer-zh-int8'; sherpa_funasr_nano 保留原 model) + 调 saveTranscriptConfig
- model onValueChange: 调 saveTranscriptConfig (之前缺)
- experimental toast '我已知晓, 切到 Nano' 确认分支: 调 saveTranscriptConfig

### ConfigContext.tsx
```diff
- const is_legacy_model = (config.model === 'sense-voice-zh-int8'
-   || config.model === 'sense-voice-zh'
-   || config.model === 'whisper'
-   || config.model === 'paraformer-zh' /* 升级到 funasr-nano-zh */);
+ const is_legacy_model = (config.model === 'sense-voice-zh-int8'
+   || config.model === 'sense-voice-zh'
+   || config.model === 'whisper');
```

'paraformer-zh' 是 FunASR-Nano provider 下合法轻量子模型, 不是脏数据.
