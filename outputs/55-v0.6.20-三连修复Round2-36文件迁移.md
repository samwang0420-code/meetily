## 根因 (Round 2)

### 真凶 #1: useMeetingData 的 prop sync effect 把新结果覆盖回去
`useMeetingData.ts:33-37` 的 sync effect 依赖 `summaryData` prop,
`useSummaryGeneration` polling 完成时调用 `setAiSummary(formattedSummary)` 写入新结果,
但只要父组件下次 re-render 传同一个 prop 引用, sync effect 又把 state 覆盖回旧值.
**修法**: 加 `lastSyncedPropRef` ref guard, prop 引用不变时不动 state.

### 真凶 #2: BlockNote force-reload 依赖 `data?.markdown` 引用, 引用不变不触发
effect 依赖 `[status, format, data?.markdown, editor]`. 但父组件 `aiSummary` state 没变时,
BlockNoteSummaryView 收到的 `summaryData` prop 引用也不变, effect 不触发.
**修法**: 改为只依赖 `[status]`, markdown 内容用 length + prefix 做去重 key.

### 真凶 #3: 全站 36 个文件用裸 `toast.error/warning/...`, 不走 sanitize
虽然 layout.tsx SafeToastBinder 会绑定 sonner 的内部 toast 引用, 但**只有通过
那 4 个引用调用的才会 sanitize**. 任何直接 `toast.error(...)` 调用绕开 binder.
我之前只迁移了 useRecordingStop / useSummaryGeneration / useMeetingData,
其他 36 个文件没覆盖 — 包括 TranscriptContext / ImportDialog /
OllamaDownload / UpdateNotification / RecordingSettings / SummaryModelSettings 等.

### 真凶 #4: RetranscribeDialog 把 error 字符串当 React child 渲染
`RetranscribeDialog.tsx:405,432` 直接 `<p>{error}</p>`, 如果 error 含 React 错误字面
或特殊字符, 渲染时炸.

### 用户看到的 "9 段模板": 不是 bug, 是缓存
`legal_consultation.json` 已精简到 5 段 (Round 1), 但 Rust 端**缓存了旧摘要**,
用户必须主动点"重新生成"才能用新模板. 截图是缓存的旧结果.
