## §64 A: 并行转录 (3 daemon 默认)

**改动文件**: `frontend/src-tauri/src/audio/sherpa_daemon.rs`

**核心改动**: 单例 `Lazy<SherpaDaemon>` 改 N 实例池。

```rust
// 旧: 单 daemon 串行
pub struct SherpaDaemon {
    inner: Mutex<Option<SherpaHandle>>,  // 单 stdin/stdout
}

// 新: N daemon round-robin
pub struct SherpaDaemon {
    inner: Vec<Mutex<Option<SherpaHandle>>>,  // N 个独立 Python child
    counter: AtomicUsize,                       // round-robin
    count: usize,                               // env MEETILY_SHERPA_DAEMONS=1-4
}
```

**配置**:
- 默认 **3 daemon**（env `MEETILY_SHERPA_DAEMONS=1..4`）
- 8GB RAM sweet spot：3 daemon = 2.1GB 模型 + 1GB app + 系统 = 5.1GB，剩 2.9GB
- 4 daemon 紧：2.8GB + 1GB + 系统，剩 1.2GB 风险 OOM

**路由**: 所有 hot path（send_request / transcribe_blocking / capability）round-robin 选 slot，callsite 零修改（import.rs / retranscription.rs / sherpa_provider.rs / parallel_processor.rs / worker.rs 不动）。

**性能预估（13430280252492828.mp4 / 828 段）**:
| daemon 数 | 串行 → 并行 | 总耗时 |
|---|---|---|
| 1 (旧) | 串行 | ~11 min |
| **3 (默认)** | **3 路并发** | **~4 min (3.7x 加速)** |
| 4 | 4 路并发 | ~3 min（紧） |

**测试**: 10/10 PASS（3 个 §64 A 新测：round-robin + clamp + pool count）

## §64 B: 磁盘 I/O 优化（hardlink + /tmp wav）

**改动文件**: 
- `frontend/src-tauri/src/audio/import.rs:402-422`
- `frontend/src-tauri/src/audio/decoder.rs:300-304 + 628-632`

**B.1 导入 hardlink**:
```rust
// 旧: std::fs::copy (写 384MB)
// 新: hard_link first, fallback copy on cross-device
match std::fs::hard_link(&src, &dst) {
    Ok(()) => info!("Section 64 hardlinked"),
    Err(AlreadyExists) => Ok(0),
    Err(_) => std::fs::copy(&src, &dst),  // 跨卷 fallback
}
```
**收益**: macOS APFS 同卷 hardlink = 0 字节写 + 0 拷贝。导入启动快 5-10s。

**B.2 SHA1 decode cache** (重复导入零 decode):
- 新模块 `audio/decode_cache.rs`
- cache key: SHA256(size_bytes + mtime_unix_secs + first_8MB) → 16-char hex 前缀
- storage: `~/Library/Application Support/cn.lixianhuiji.app/decode_cache/{key}.bin`
- bincode 序列化整个 `DecodedAudio` (samples Vec<f32> + sample_rate + channels + duration_seconds)
- 8-byte magic `MTCACHE\x01` + payload, deserialize fail 自动清理
- import.rs decode 路径: 先 cache_key_for_file → load_cached hit → 跳 100% decode, miss → decode + save
- 1.5GB 音频: cache miss 时 ~30-60s decode → cache hit 时 ~2s (bincode deserialize)

**B.3 /tmp wav for ffmpeg decode**:
```rust
// 旧: tempfile_in(parent_dir) → 写原卷 APFS (慢)
// 新: tempfile_in(std::env::temp_dir()) → 写 /tmp APFS tmpfs (快 3-5x)
```
**约束**: ffmpeg input/output 不走 hardlink，cross-device 不影响（§64 B.1 是 hard_link 文件本身）。

**收益**: 1.08GB wav 写盘从 ~30s → ~6s（tmpfs）。

## §64 C: 摘要 max_tokens 800 上限

**改动文件**: `frontend/src-tauri/src/summary/processor.rs`

```rust
// 旧: DEFAULT_SUMMARY_MAX_TOKENS: u32 = 1200
// 新: DEFAULT_SUMMARY_MAX_TOKENS: u32 = 800
```

**理由**: qwen3.5:2b CPU 推理 30 tok/s
- 1200 token 输出 → ~41s/chunk
- **800 token 输出 → ~27s/chunk**（节省 34%）
- 23K chars 摘要: 9 chunks × 41s = 6 min → 9 chunks × 27s = 4 min

**单测**: 35/35 PASS（5 断言更新 1200 → 800，区间 800-1200）

## 铁律（任何 v0.X 演进适用）

1. **多 daemon 默认 3** — 8GB sweet spot；4+ 紧。env `MEETILY_SHERPA_DAEMONS=1-4` 显式覆盖
2. **round-robin 用 AtomicUsize + Relaxed** — 不需要严格时序，fetch_add % count
3. **hardlink 同卷优先** — 跨卷 / 不支持时 fallback copy
4. **/tmp wav 安全** — ffmpeg input/output 不走 hardlink，cross-device OK
5. **max_tokens ≤ 1200 for CPU 2B** — 单测守卫 400 ≤ DEFAULT ≤ 1200
6. **§28 三处同步** — 代码 + AGENTS.md §X + Obsidian 决策日志同日落
