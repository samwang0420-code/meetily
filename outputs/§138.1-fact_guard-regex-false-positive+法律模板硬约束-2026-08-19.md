# §138 摘要质量根因修复 — fact_guard regex false positive + 法律模板硬约束

**触发**: 用户 8/19 检查最近摘要, 发现:
- 911f52ae (魏某专利案) 摘要把"二零二二年七月" 错改成 "2022 年 5 月" (实际是"7月") — 日期错误
- 911f52ae 摘要多处出现"未提及具体姓名"/"未在提供的文本片段中详细记载"/"模糊表述" 等逃避语 — 反模式
- 911f52ae 摘要元数据"庭审日期未明确" 但事实时间线又写"2024 年 5 月 29 日开庭" — 自相矛盾
- fact_guard 报"原文含重量/容量单位" 警告 — 但实际 transcript 0含重量单位 — false positive

## 根因分析 (3 个独立 bug)

### Bug 1: WEIGHT_UNIT_RE 严重 false positive
```rust
// 旧 regex (line 30):
r"(?x)(?:\d[\d,]*|[一-鿿]+)(?:\.\d+)?\s*(?:克|公斤|千克|kg|g|mg|毫升|升|L|ml)"
```
- `[一-鿿]+` 接受任意中文字符 + 后接单位字符
- 实测: "巧克力很甜" → 误判 "巧克" 是 "重量"; "提升" 含"升" → 误判; "开庭" 含"庭"... etc.
- 用户 911f52ae transcript 大量"提升/上升/开庭/上诉"都被命中

### Bug 2: MONEY_UNIT_RE 同样 false positive
```rust
// 旧 regex (line 29):
r"(?x)(?:\d[\d,]*|[一-鿿]+)(?:\.\d+)?\s*(?:元|块|万美元|美元|人民币|dollars?)"
```
- "判决金额为五万元" + "原告是公司" → 含"元/公"被命中
- 法律摘要几乎每段都命中 → 警告无意义

### Bug 3: DATE_RE 不能识别中文数字日期 + 不容忍空格
```rust
// 旧 regex (line 23):
r"(?x)20\d{2}年(?:\d{1,2}月(?:\d{1,2}[日号])?)?|\d{1,2}[月/-]\d{1,2}(?:日|号)?"
```
- 911f52ae transcript 实际全是"二零二二年七月"/"二零二四年五月二十九日" 这种**中文数字日期**, 完全不匹配
- AI 摘要写"2022 年 5 月" — 阿拉伯数字 + 空格分隔, 也不匹配 (regex 没容忍空格)
- 结果: fact_guard 的 source_dates 和 summary_dates 都接近空集, AI 摘要随便改写日期都蒙混过关

### Bug 4: 法律模板"未明确提及" 反模式
- 模板 instruction 已经写"禁止用'未提及'填空", 但模型仍用"未提及具体姓名"/"未在提供的文本片段中详细记载" 等变种
- 缺更显眼的硬约束, 直接命名禁止字眼

## 修复

### Bug 1/2/3 — fact_guard.rs regex 重写

**WEIGHT_UNIT_RE** (line 30-):
```rust
// §138: 必须以数字/中文数字开头, 否则 "巧克力" "麦克风" "提升/上升/开庭" 都被误判
r"(?x)
(?:
    # 1. 阿拉伯数字 + 重量单位: 5克 / 1.2公斤 / 500kg
    \d[\d,]*(?:\.\d+)?\s*(?:克|公斤|千克|kg|g|mg|毫升|升|L|ml)
    |
    # 2. 中文数字 + 重量单位: 五克 / 一千千克 / 五百毫升
    [零一二二三四五六七八九十百千]+(?:\s*[零一二二三四五六七八九十百千]+)?\s*(?:克|公斤|千克|毫升)
)
"
```

**MONEY_UNIT_RE** (line 29-):
```rust
// §138: 必须以数字/中文数字开头, 否则 "判决" "原告诉求" "元素" 等中文词含"元"被误判
r"(?x)
(?:
    # 1. 阿拉伯数字 + 货币单位: 100元 / 1.5万元 / 99美元
    \d[\d,]*(?:\.\d+)?\s*(?:元|块|万元|万[元美]?美元?|美元|人民币|dollars?)
    |
    # 2. 中文数字 + 货币单位: 一百元 / 三万元 / 三万 / 十万美元
    [零一二二三四五六七八九十百千]+(?:\s*[零一二二三四五六七八九十百千]+)?\s*(?:元|块|万元|万|万[元美]?美元?|人民币)
)
"
```

**DATE_RE** (line 23-):
```rust
r"(?x)
(?:
    # 1. 阿拉伯数字日期 (容忍空格): 2024年5月29日 / 2024年5月 / 5月29日 / 5/29
    20\s*\d{2}\s*年(?:\s*\d{1,2}\s*月(?:\s*\d{1,2}\s*[日号])?)?
    |\s*\d{1,2}\s*[月/-]\s*\d{1,2}\s*(?:日|号)?
    |
    # 2. 中文数字日期 (容忍空格): 二零二四年五月二十九日 / 二零二四年五月 / 五月二十九日
    [零一二二三四五六七八九十百千]+\s*年(?:[零一二二三四五六七八九十百千]+\s*月(?:[零一二二三四五六七八九十百千]+\s*[日号])?)?
    |[零一二二三四五六七八九十百千]+\s*月[零一二二三四五六七八九十百千]+\s*[日号]
)
"
```

### Bug 4 — 法律模板硬约束 (`frontend/src-tauri/templates/court_hearing.json` + `legal_consultation.json`)

`事实时间线 / Key Events Timeline` section 的 `instruction` 字段**末尾**追加 §138 硬约束 (6 条):
1. **日期 verbatim**: 原文中'二零二二年七月'不能改写成'2022年5月'. 阿拉伯数字日期和中文数字日期保持原文形式.
2. **金额 verbatim**: '167万余元' 不能改写为 '167万' 或 '1.67百万'.
3. **人名 verbatim**: 原文用'魏某'就写'魏某',原文用'魏立秋'就写'魏立秋',不要自动补全化名.
4. **因果不颠倒**: '因A所以B'顺序不能改写.
5. **禁止逃避语**: 严禁出现'未提及具体姓名'/'未在提供的文本片段中详细记载'/'模糊表述'/'未明示'/'未明确提及具体姓名'/'转录未明确提及'等回避语. 信息不足直接写'信息不明确'或省略该字段,不绕弯子.
6. **单位不换算**: 克/公斤/毫升 与 元/块/美元 不可互换, 数字必须 verbatim.
