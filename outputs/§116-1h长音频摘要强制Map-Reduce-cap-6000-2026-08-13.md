# §116 1h 长音频摘要强制 Map-Reduce (token_threshold cap 6000)

**日期**: 2026-08-13
**分支**: `fix/section-116-cap-local-summary-threshold` (从 main 拉出)
**关联**: §36 (Map-Reduce 触发) / §52 (max_tokens 800) / §55 (chunk 2400) / §115 (Git workflow)
**根因会议**: `meeting-28a6c63c-4328-46ce-b637-50ce2c5364d8` (1h47m / 26,302 chars / 6576 tokens)

---

## 1. 问题

用户实测 1h47m 音频录入后,摘要生成 **3 分 21 秒** 完成, **chunk_count = 1** (走了 single-pass).

**期望**: 长音频应走 Map-Reduce, **chunk_count ≥ 3**, 时间分布到 4 chunk × 30s ≈ 2 min.

**根因** ([service.rs:434, 458]: 修复前):

```rust
// Ollama 路径
let optimal = metadata.context_size.saturating_sub(300);  // qwen3.5:2b 32K → 32468

// BuiltInAI 路径
let optimal = model_def.context_size.saturating_sub(300) as usize;  // 同样 32468
```

- `metadata.context_size = 32768` (Qwen3.5-2B 模型声明)
- `32768 - 300 = 32468` 即 token_threshold
- 用户 6576 token < 32468 → **永远走 single-pass**, Map-Reduce 触发条件 `LOCAL_SUMMARY_CHUNK_THRESHOLD = 1800` 永远摸不到

---

## 2. 修复

加 `LOCAL_SUMMARY_TOKEN_CAP = 6000`,Ollama/BuiltInAI 路径 `.min(6000)` 强制 clip.

**改动** ([frontend/src-tauri/src/summary/service.rs]: L48-60, L447, L472):

```rust
// §36 LOCAL_SUMMARY_CHUNK_THRESHOLD = 1800
pub const LOCAL_SUMMARY_CHUNK_THRESHOLD: usize = 1800;

// §116 LOCAL_SUMMARY_TOKEN_CAP = 6000
// Why: Ollama/BuiltInAI providers expose huge context_size (Qwen3.5-2B → 32K),
// so metadata.context_size.saturating_sub(300) = 32468. Without a cap, a 1h+
// audio transcript (6576 tokens) is processed as a single-pass prompt, which:
//   1. wastes 32468-token prompt budget for ~6K tokens of real content
//   2. forces LLM to maintain coherence across many minutes of speech
//   3. silently skips the Map-Reduce branch (LOCAL_SUMMARY_CHUNK_THRESHOLD = 1800)
// Cap to 6000 forces Map-Reduce for any local summary > 6000 estimated tokens.
// Cloud providers (OpenAI/Claude/Groq/OpenAI-Custom) keep their 100000 threshold
// since they handle large contexts natively.
pub const LOCAL_SUMMARY_TOKEN_CAP: usize = 6000;

// Ollama 路径 (line 447)
let optimal = metadata.context_size.saturating_sub(300).min(LOCAL_SUMMARY_TOKEN_CAP);

// BuiltInAI 路径 (line 472)
let optimal = model_def.context_size.saturating_sub(300).min(LOCAL_SUMMARY_TOKEN_CAP as u32) as usize;
```

**Cloud 路径** (line 487+): `100000` 不动,云端 API 在大 context 上有 native 优势.

## 3. 性能预测 (meeting-28a6c63c)

| 方案 | token_threshold | chunk_count | Map chunks | Reduce | 总耗时 |
|---|---|---|---|---|---|
| 旧 (无 cap) | 32468 | 1 | 1 (1h47m 单 prompt) | 0 | 3:21 |
| **§116 (cap 6000)** | **6000** | **4** | **4** | **1** | **~2 min** |

6576 token > 6000 cap → 走 Map-Reduce → 4 chunks × ~30s = 2 min (含启动 30s).

## 7. 已知边界

- 6000 cap 拍板依据: 6576 token (1h47m) 实际工作. 1h-1.5h 范围都覆盖.
- 极短 audio (< 5min, < 1000 tokens) 仍走 single-pass (不触发 chunk).
- cloud 路径 (OpenAI/Claude/Groq) 不受 §116 影响, 100000 阈值保留.
- onnx 模型 local inference 串行 (llama-helper single instance), 4 chunks 实际串行处理 ~ 2 min 总耗时.
