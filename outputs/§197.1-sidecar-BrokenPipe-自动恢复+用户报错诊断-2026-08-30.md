## 真根因: stale is_healthy after child death

"Failed to write request to stdin" 来自 `frontend/src-tauri/src/summary/summary_engine/sidecar.rs:381`:
```rust
stdin
    .write_all(request_json.as_bytes())
    .await
    .context("Failed to write request to stdin")?;
```

`write_all` 返回 `BrokenPipe` (io::ErrorKind::BrokenPipe) 当 child process 已死, OS 关闭 stdin pipe。**但 `is_healthy` flag 仍是 true**:

```rust
pub async fn ensure_running(&self, model_path: PathBuf) -> Result<()> {
    let current_model = self.current_model_path.read().await;
    if current_model.as_ref() == Some(&model_path) && self.is_healthy() {
        return Ok(());  // ❌ 没 try_wait 真实检测 child 状态
    }
    self.spawn(model_path).await
}
```

**stale is_healthy 触发场景**:
1. 上一次 generate 完成 → health_check_loop 30s 后 ping → child 可能已退出 (OOM kill / 模型加载崩溃 / 显式 kill / 沙箱 killed)
2. 用户点击 regenerate → `ensure_running` 调用 → `is_healthy` 还是 true (从 spawn 后就没改)
3. `send_streaming_request` → 拿 in_flight lock → 拿 stdin_writer lock → `write_all` → **BrokenPipe**
4. 错误冒泡: `Failed to write request to stdin` → summary_processes.status='failed'

**为什么 health_check_loop 没救场**:
```rust
fn start_health_check_loop(&self) {
    tokio::spawn(async move {
        let mut interval = tokio::time::interval(Duration::from_secs(30));
        loop {
            interval.tick().await;
            // ...
            if manager.active_request_count.load(Ordering::SeqCst) > 0 {
                continue;  // ❌ skip ping during active request
            }
            // ...
        }
    });
}
```

**两个 race**:
1. 健康检查只在 idle 时跑 (active_request_count > 0 时 skip)
2. 即使 health_check 跑了, is_healthy 改 false 是异步的, 下一次 request 可能立刻拿旧值

## 修复 (3 处)

### 1. ensure_running 加 try_wait 探针

```rust
pub async fn ensure_running(&self, model_path: PathBuf) -> Result<()> {
    // §197.1 (2026-08-30): liveness probe via try_wait().
    let needs_respawn = {
        let mut child_lock = self.child_process.lock().await;
        if let Some(child) = child_lock.as_mut() {
            match child.try_wait() {
                Ok(Some(status)) => {
                    log::warn!(
                        "§197.1 sidecar child exited unexpectedly (status={}); spawning fresh",
                        status
                    );
                    true
                }
                Ok(None) => false, // still alive
                Err(e) => {
                    log::warn!("§197.1 try_wait failed: {}", e);
                    false
                }
            }
        } else {
            false
        }
    };
    if needs_respawn {
        // Clear stale handles
        *self.stdin_writer.lock().await = None;
        *self.stdout_reader.lock().await = None;
        *self.current_model_path.write().await = None;
        self.is_healthy.store(false, Ordering::SeqCst);
    }

    // 原有 model 检查 + spawn 逻辑保持不变
    // ...
}
```

**try_wait 是非阻塞的** (调用一次立刻返回, 不像 wait() 会阻塞等子进程结束). 每次 request 都跑一次, overhead < 1ms.

### 2. send_request / send_streaming_request 加 BrokenPipe 自动恢复

新增 helper 方法:

```rust
async fn try_write_request_to_stdin(&self, request_json: &str) -> Result<()> {
    let mut stdin_lock = self.stdin_writer.lock().await;
    let stdin = stdin_lock.as_mut().ok_or_else(|| anyhow!("Sidecar not running"))?;
    stdin
        .write_all(request_json.as_bytes())
        .await
        .context("Failed to write request to stdin")?;
    stdin
        .write_all(b"\n")
        .await
        .context("Failed to write newline")?;
    stdin.flush().await.context("Failed to flush stdin")?;
    Ok(())
}

async fn write_request_with_recovery(&self, request_json: &str) -> Result<()> {
    match self.try_write_request_to_stdin(request_json).await {
        Ok(()) => Ok(()),
        Err(e) => {
            let is_broken_pipe = e
                .downcast_ref::<std::io::Error>()
                .map(|io_err| io_err.kind() == std::io::ErrorKind::BrokenPipe)
                .unwrap_or(false);
            if !is_broken_pipe {
                return Err(e);
            }
            log::warn!(
                "§197.1 BrokenPipe writing to sidecar stdin; respawning and retrying once"
            );
            self.is_healthy.store(false, Ordering::SeqCst);
            let model_path = self
                .current_model_path
                .read()
                .await
                .clone()
                .ok_or_else(|| {
                    anyhow!("§197.1 cannot respawn: no current_model_path recorded")
                })?;
            let _ = self.shutdown().await;
            self.spawn(model_path).await?;
            self.try_write_request_to_stdin(request_json).await
        }
    }
}
```

**send_request / send_streaming_request** 简化:
```rust
// Before:
{
    let mut stdin_lock = self.stdin_writer.lock().await;
    let stdin = stdin_lock.as_mut().ok_or_else(|| anyhow!("Sidecar not running"))?;
    stdin.write_all(...).await.context("Failed to write request to stdin")?;
    stdin.write_all(b"\n").await.context(...)?;
    stdin.flush().await.context(...)?;
}

// After:
// §197.1: write with BrokenPipe recovery (respawn + retry once)
self.write_request_with_recovery(&request_json).await?;
```

**两层防御**:
- L1: ensure_running try_wait 探针 → 99% 场景下 stale is_healthy 在 write 前已被修正
- L2: write_request_with_recovery → 捕获 ensure_running 后 race window (child 在 try_wait 后死)

## 铁律 (任何 v0.X 演进适用)

1. **sidecar manager 必须有真实 liveness 探针** — `is_healthy` flag 单独不够, 必须 `try_wait()` 交叉验证
2. **write_all BrokenPipe 触发自动 respawn** — 不要让用户重启 app 救场
3. **try_wait() 是非阻塞且廉价** — 每次 request 都跑一次, < 1ms overhead
4. **健康检查不能只在 idle 时跑** — race 窗口 (idle 30s) 必须有第二层防御
5. **bundle sync 必须实测 sha** — sync_app_bundle.sh 报告成功 ≠ bundle binary 是新内容 (codesign 重签会改 sha)
6. **stale is_healthy 是 silent bug** — 用户只在"重新生成"时才发现, 已经触发 9 分钟 timeout 累计浪费
