## 已实施 (A 路径, 最优性价比)

### 1. sherpa_asr.py - 新增 streaming pipeline (385 → 700+ 行)
- `stream_begin` - 开 session, 记录 model/hotwords/sample_rate
- `stream_chunk` - 推 audio chunk, 返回 `partial` + `delta` + `is_endpoint`
- `stream_finalize` - 清理残留 buffer, 出最后 final
- 算法: 累计缓冲 ≥ 600ms 才跑 offline decode, 30ms 滑窗 + RMS -45dB 静音 ≥ 1200ms 触发 endpoint 切句
- 测试: 6s 合成音 4 chunks, 每 chunk decode ~30-80ms (Paraformer 模型)

### 2. sherpa_daemon.rs - Rust 端桥接
- 加 `stream_begin` / `stream_chunk` / `stream_finalize` 三个方法
- 加 `send_request` JSON 通用 bridge
- 加 `#[tauri::command]` 三个暴露给前端调用
- lib.rs 注册

### 3. transcription/worker.rs - Sherpa branch 改造
- 不再每次 chunk 跑整段识别, 改成推给 streaming session
- 维护静态 `SHERPA_STREAM_SESSION` (per chunk_id atomic 决定新会话)
- resample 16kHz 强制 (3 倍 / 6 倍下采样)
- chunk 内 partial → emit `transcript-partial` 事件 (不进 transcript-update)
- is_endpoint + delta → emit `transcript-update` final 段

### 4. transcriptService.ts - Frontend listener
- `onTranscriptPartial` 监听 `transcript-partial` 事件

### 5. TranscriptContext.tsx - Frontend state
- `livePartialText: string` + `isPartialEndpoint: boolean`
- partial 句子完成 (is_endpoint + delta) 后自动清空
