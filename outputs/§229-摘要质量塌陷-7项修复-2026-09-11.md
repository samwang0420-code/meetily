## 根因 (3 层)

### 根因 1: §185.6 多案件检测器漏法人案
- 老 `detect_cross_case_pollution` 只识别 `被告人X/罪犯X/被告X` 3 个前缀
- 不识别 `重庆通航融资租赁公司 + 山西神飞公务机有限公司` 法人
- transcript 含 "重庆通航"4 次 / "山西神飞" 6 次 都漏检
- `fact_guard.cross_case_pollution: []` 空 → §165 wrap 不触发 → 整案当 single-case 走

### 根因 2: §165 wrap 触发条件失配
- 老 wrap 只信 cross_case_pollution, 法人案从未触发过
- 没有 fallback 到 transcript 主角分群检测

### 根因 3: 6 个 prompt 缺强约束
LLM 在 6 个维度偷懒:
- 争议焦点/待查明事项: 写"无明显争议"
- 时间线: 按重要性排, 不按时间排
- 表格: 内容塞单列, 其他列填 `-`
- 证据: 把人名当证据名
- 案由: 笼统 "合同纠纷"
- 表格行: 列填充占位符

- multi_case_transcript 第一次输出 16 个 parties 全是 ASR 噪音:
  - "态度" / "员李" / "向周" (narrative "态度强硬" / "李经理" / "向周局长报告" 误匹配 PERSON_RE 单次)
  - "限公司与山西神飞" / "出租给山西神飞" (ASR 拼接错位,regex 命中跨实体边界)
  - **完全没有 "重庆通航" / "山西神飞"** (核心公司都漏)
- §165 wrap 不触发 → result 不是 JSON 数组 → 单案件走 → 飞机案仍失踪

### 根因 (3 跳 + 1 关键 bug)

1. **PERSON_RE 缺前缀** — 原 7 前缀覆盖"被告人X"等法庭称谓,但 `市人大代表洪某向陈某一家借款` 这种"民间借贷 + 人大代表身份"场景漏检
2. **ENTITY_RE 直接捕获整段** — `重庆通航融资租赁有限公司` 整段被捕获成 legal_entity,后续 core 截取太复杂
3. **频次过滤缺失** — narrative "态度强硬" / "李经理" / "向周局长报告" 单次 PERSON_RE 匹配都通过,产生大量噪音
4. **🔴 关键 bug: `core.len() > 4` 是 UTF-8 byte length** — 中文每个字 3 bytes, `"重庆通航"` 实际 byte len = 12 > 4,导致核心公司名永远被过滤掉!

### 修复 (5 项 §229A.1-A.5)

#### §229A.1: PERSON_RE 加 7 前缀
```rust
// 原 (漏检 "市人大代表洪某"):
//   被告人|罪犯|被告|原告|申请人|被执行人

// 新 (覆盖 5 角色 + 7 前缀):
//   被告人|罪犯|被告|原告|申请人|被执行人
//   + 市人大代表|人大代表|代表|主任|书记|律师|代理人
```

#### §229A.2: ENTITY_CORE_RE 改 non-greedy + suffix capture
```rust
// 原: ENTITY_RE r"[\u4e00-\u9fa5]+(?:融资租赁|公务机|航空|有限)公司"
//   - 捕获整段 (含前缀地名), 后续 core 截取困难

// 新: ENTITY_CORE_RE r"([\u4e00-\u9fa5]{2,4}?)(融资租赁(?:有限)?公司|公务机(?:有限)?公司|航空(?:有限)?公司|有限责任公司|有限公司)"
//   - non-greedy 2-4 字 + 后缀完整 capture
//   - "重庆通航融资租赁有限公司" → group(1) = "重庆通航", group(2) = "融资租赁有限公司"
```

#### §229A.3: 频次过滤 ≥ 2
```rust
// natural_person 频次 < 2 排除 (narrative "态度强硬" / "李经理" 单次匹配)
// legal_entity 频次 < 2 排除 (ASR 拼接错位 "限公司与山西神飞" 单次匹配)
```

#### §229A.4: 🔴 关键 bug 修复
```rust
// 错: core.len() > 4      (UTF-8 byte length, 中文 12 bytes > 4 永真)
// 对: core.chars().count() > 4  (实际字符数)
let core_chars = core.chars().count();
if core.is_empty() || stop_words.contains(&core) || core_chars < 2 || core_chars > 4 {
    continue;
}
```

### 铁律 (任何 v0.X 演进适用)

1. **Rust `str.len()` 是 UTF-8 byte length** — 中文字符判断必须用 `chars().count()`,这是 §229A.4 关键 bug 修复的核心教训
2. **regex crate 默认不支持 look-around** — 用 non-greedy `{2,4}?` + suffix capture group 提取 prefix
3. **频次过滤 ≥ 2 是 ASR 转录必备** — narrative 句子 ("态度强硬" / "李经理") 单次匹配必然引入大量噪音
4. **§165 老测试可能受 §229 改动影响** — 改 wrap 触发条件后必须重跑 p165 测试,可能需要让人名重复 2 次
5. **debug test 必跑真实数据** — 单元 mock 测不出 core.len() vs chars().count() 这种 UTF-8 长度 bug,只在 c1299582 真实切片上才暴露
6. **guard anchor regex 必须跟实际 regex 同步** — §229A.2 改了 ENTITY_CORE_RE 写法后, anchor `229_a_entity_re_includes_rongzi_zulin` 的 regex `融资租赁公司.*?公务机.*?航空.*?有限责任公司` 找不到同一行匹配(实际是 OR 形式),改成 `融资租赁.*?公务机.*?航空.*?有限责任公司` 才 PASS
