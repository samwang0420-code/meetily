# W2.6 — v0.5.0b Topbar 修复 + binary 重编（2026-07-10）

## 截图回报问题（用户上传）
- App **顶部没有新写的 Topbar**，而是老的 v0.4.0 sidebar（"Meetily" 标题 / "Home / Meeting Notes / Start Recording" 老式布局 / footer 显示 v0.4.0）
- Sidebar 也没有 v0.5.0b 设计的 Workspace / Library / Configure 分组
- 语言切换按钮仍在 sidebar 里，没上 Topbar

## 根因（深度排查后确认）
**binary 没嵌入新 chunks**。时间线：

```
23:31  Topbar.tsx / Sidebar 新代码写好
00:02  next build 完成 → out/_next/chunks/998-f3ac...js (44KB, 含 Topbar code) 生成
00:06  cargo build 完成 → target/release/meetily (66MB, PID 52701 跑着)
       ↳ 但是 binary 内嵌的 998-f3ac...js 区域实际是 122KB 老版本
         因为 tauri_build::build() 在 cargo 启动那一刻拍快照 frontendDist
         而 rustc 增量链接时没重新读 frontendDist 副本
```

验证：
- out/ 998 chunk 含 `from-blue-500 to-purple-600` 2 hits
- binary 998 chunk 区域 0 hits（全是乱码 = 老版本）
- binary 含 `'中文' 6 hits`（Topbar LOCALE_LABEL 嵌入）

## 修复操作
1. `pkill -9 next build`（重叠 3 个进程）
2. `rm -rf .next/cache .next/server/app .next/static/chunks`（清狠了，触发全量）
3. `next build` output export 模式（4 分钟），产物落到 `frontend/out/`
4. **关键**：`cd src-tauri && cargo build --release`（30 分钟增量），触发 tauri_build::build() 重打包 frontendDist 进 binary
5. 最终 binary：66.3 MB，mtime 2026-07-10 00:36:08，启动 PID 67004

## 验证
- ✅ binary 启动 5 秒无 panic
- ✅ RUST_LOG 显示 onboarding step 4、API key 加载、`language preference = zh`
- ✅ binary 含 `'中文' 6 hits`（Topbar 嵌入证据）
- ⏳ **用户验证待**：Cmd+Q 完全退出 → 重开 → 应看到 Topbar + Sidebar 分组

## 教训
1. **不要主动 `rm -rf .next/static/chunks`**：触发 next build 全量
2. **改 frontend 必跑 `cargo build --release`**：Tauri 1.x 资源 embed 由 build.rs 在 cargo 启动时做，rustc 不会感知 frontendDist 变化
3. **后台脚本必须 nohup + /tmp/*.log 重定向**：screen/dash 子进程会被 shell timeout 杀
4. **memory tight 16GB**：cargo 编译时仅剩 60MB free，编译结束时降回 4GB free
