## 修复 (4 件)

### §184.1 markdown table 行 dedup
`frontend/src-tauri/src/summary/hard_post_process.rs::dedup_markdown_table_rows(md: &str) -> (String, TableDedupReport)`:
- 检测 markdown 表格块 (以 `|---|` 行为界)
- 比较每个 data row 的列 1+2+3 拼接去空白 → 主列相同 → 留首行, 删重复
- 返回 (deduped_md, report with rows_removed / total_rows_before / total_rows_after)

### §184.2 raw transcript leak 截断
`hard_post_process.rs::truncate_raw_transcript_leak(md: &str) -> (String, RawTranscriptLeakReport)`:
- 检测 ASR 错位特征: 6+ 连续 `的/啊/嗯/呃/哦` 字面段
- 找到第一个 leak 位置 → 截断该行 + 加 `(原始转录错位内容已截断)` 提示
- 返回 (truncated_md, report with segments_truncated / total_chars_removed)

### §184.3 effective_temperature 0.7 → 0.3
`service.rs::effective_temperature`:
- regenerate 路径 + Ollama/BuiltInAI → 0.3 (原 §169.1 0.7)
- 0.3 是 §163 默认 0.1 与 §169.1 原 0.7 之间的折中
- 既保留一定随机性让 regenerate 输出不同于上次, 又能保证输出结构稳定

### §184.4 撤回 court_hearing.json §183 instruction 注入
`frontend/src-tauri/templates/court_hearing.json`:
- `案件基本信息` 段 instruction 中撤回 `【§183】二审案件当事人标注严格格式...` + `【§183】时间线覆盖度...`
- §183 规则改放在 `description` 末尾 (`【§184 立场标注 + 时间线覆盖度 (全局规则, 由后端 §184.1 dedup + §184.2 truncate 兜底)】`)
- 不污染 prompt 主指令 (instruction 是 LLM 每段都读的; description 是模板介绍)

1. **markdown table 行 dedup 必须靠主列拼接** — 不能用全行 hash (微小标点差异就算不同), 必须按业务决定的"主列"拼接去空白比较
