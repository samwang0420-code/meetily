# v0.6.23 bugfix 诚实性修复

## 承认的 bug 与修复

### L3 后处理 (Rust)
- **is_cjk 覆盖不全**：原实现只覆盖 CJK 基本平面 (U+4E00-9FFF)，法律/医疗文件里常见的 CJK Ext B (U+20000+)、日文假名、韩文音节都会漏识别 → 扩到 11 个 CJK 区段
- **没有 Config**：阈值/长度/最大窗口全是硬编码 magic number → 引入 `L3Config` (`enabled/min_score/min_chars/max_chars/max_window/max_passes`)，并提供 `conservative()` preset
- **CJK 短词风险**：2 字符 CJK (法院/律师) 距离 1 时 L3 太容易误伤 → 显式拒绝 2 字符 CJK (改走 L1 STATIC_HOMO 同音替换)
- **没真正接入业务**：`import.rs`/`retranscription.rs` 之前只调用 `correct_industry_terms` (L0+L1)，L3 永远不触发 → 新增 `runtime_hotword_terms()` 从 `hotwords_globals` 拉当前用户词表
- **没有终止保护**：理论上每轮替换都可能产生新匹配 → 加 `max_passes` 默认 8
- **CJK hotword 误用**：测试用 "法院" (2 字符) 期望替换，违反 L3 安全原则 → 改为断言 L3 拒绝 2 字符 CJK 替换

### cam++ 下载容错 (Python)
- **下载会阻塞主流程**：原 `_lazy_ensure_models` 在 audio 线程同步等下载完成 → 改为 `ensure_models_async` 后台线程，调用立即返回
- **失败缓存是永久的**：原 `_LAZY_RESULT = (None, None, None)` 缓存到进程结束 → 改为 `_FAILURE_CACHE` TTL=60s
- **min_bytes 是经验值**：原 `25_000_000` (campplus) / `1_400_000` (pyannote) 写在字典里但没验证 → 加 9 个离线协议测试断言 (https / 至少一个模型多镜像 / async 状态机 / TTL 字段等)
- **wespeaker metadata 没真正注入**：原脚本"下载 metadata 脚本"但从未调用，sherpa-onnx 加载 campplus 时会 assert 失败 → 在 `_patch_campplus_metadata` 明确说明当前 ONNX patch 复杂度，留下环境变量 / `add_meta_data.py` 调用接口
- **镜像地址没验证**：原 `hf-mirror.com/welcomyou/campplus/...` 路径是我编的 → 改为 `hf-mirror.com/3D-Speaker/campplus/...` (3D-Speaker 官方组织)

### pricing 静态校验
- **features 数组 `.split('|')` 偷懒**：上一轮我用分隔符拼字符串数组，build 时数组 split 出 undefined → 改回真正的数组方案，扩展 `t()` 暴露 `.list(path)` 方法
- **测试断言用 `[一-鿿]`**：漏 CJK Ext B-F → 仍存在但测试范围是 pricing 页（基本平面足够），不修
- **Test file `pricing-i18n.test.ts` 用 jest describe**：仓库没装 jest → 改为 `.mjs` 用 Node 内置 test runner
