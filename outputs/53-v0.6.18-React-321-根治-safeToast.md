# 53 · React #321 根治：safeToast 全局防御

> 日期: 2026-07-19 · 版本基线: v0.6.18 → v0.6.19
> 触发: 用户多次反馈"Failed to save meeting. Minified React error #321; visit https://react.dev/errors/321 ..."

## 根因
- 之前一直在做 toast 兜底 (try/catch 包 toast.error / 用 CardBoundary 捕获),
  但 `String(error)` 拿到的是字符串 "Minified React error #321; visit https://react.dev/errors/321 ...",
  sonner 把它塞进 description → description 渲染时 React reconciler 再炸一次 (#321).
- 之前的 `isReactInternal = /Minified React error #\\d+/.test(msg)` 正则只在 msg 起始就是 React error 字面时才命中, 嵌在长字符串中间或被包装过的对象识别不出来.

## 解法 (一行总结)
**description 强制 sanitize + 全局 sonner 绑定 + 全站点 toast 迁移到 safeToast**

## 代码改动 (4 个文件)
1. `frontend/src/lib/safeToast.ts` (新增, 165 行)
   - `safeString(input)`: 把任意值转纯字符串 (Error → "Name: msg", null → '', 不可序列化 → fallback)
   - `sanitizeDescription(input, kind)`: 命中 React error 模式 → 中文 fallback; 多行归一; 截断 500
   - `safeToast.{error,success,warning,info}(msg, opts)`: opts 走 sanitizeDescription, 内部 try/catch 终极兜底
   - `bindSonner({error, success, warning, info})`: 替换内部引用, 让裸 `toast.error` 也走 sanitize

2. `frontend/src/app/layout.tsx` (+12 行)
   - 新增 `<SafeToastBinder />` 挂在 Toaster 之前
   - mount 时把 sonner 的 `toast.{error,success,warning,info}` 绑给 safeToast
   - 效果: **任何直接 `toast.error('x', { description: err })` 调用都自动 sanitize**

3. `frontend/src/hooks/useRecordingStop.ts`
   - import toast → safeToast, 所有 `toast.<level>(` → `safeToast.<level>(`
   - 之前的 isReactInternal 分支保留 (双保险)

4. `frontend/src/hooks/meeting-details/useSummaryGeneration.ts`
   - 17 处 toast.<level> 全部迁移 → safeToast
   - 包括 line 219/247/383 的 summary.status_error, line 487/506/518/531/546/580/594/606/619 的 model 类错误

5. `frontend/src/hooks/meeting-details/useMeetingData.ts`
   - saveAllChanges catch 块 `toast.error(t('summary.save_failed'), { description: String(error) })` → safeToast
