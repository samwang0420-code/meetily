## 改动详情

### 1. `court_hearing.json` 模板重写 (5 处硬约束)

**description 改硬约束 (5 条零X约束)**:
- 严禁推测判决结果 → 庭审未宣判时一律写"本案择期宣判"或留空
- 严禁角色混淆 → 证人/辩护人/公诉人/被告人 身份绝对不可混用
- 严禁人名漂移 → 同一主体原文姓名 verbatim, 禁止同音近形变体
- 严禁已查实事项混入待查明
- 仅供案件纪要参考, 不构成正式法律文书

**删除 narrative 段的「一审 {判决}, 二审 {焦点}」placeholder** — 这是 LLM 诱导编造判决的根因

**5 段 instruction 各加 §148 §1/§2/§3 强约束**:
- 事实时间线: 表格 | 时点 | 阶段 | 关键事件 | 参与方 + 证据, 终点若是"休庭/择期宣判", 关键事件必须写"本案择期宣判"
- 控辩主张: 角色准确 (亲属不 = 辩护人), 建议/意见显式标记
- 关键证据: 证人证言必须明确写"证人身份: XX 的姐姐", 不写"辩护人 XX姐姐"
- 争议焦点: 显式区分控方/辩方主张
- 待查明事项: 待补强 + §1 已查实标注

### 2. `fact_guard.rs` (548 → 866 行, +318)

**FactGuardReport 加 3 字段**:
```rust
pub name_drift: Vec<String>,           // §148 §1
pub role_confusion: Vec<String>,       // §148 §2
pub fabricated_verdict: Vec<String>,   // §148 §3
```

**is_legal_critical()** — 任一命中即 SEVERE (单条也降级):
```rust
pub fn is_legal_critical(&self) -> bool {
    !self.role_confusion.is_empty() || !self.fabricated_verdict.is_empty()
}
```

**detect_name_drift()** — 100+ 常见姓氏前缀过滤 + 字符位替换生成 variant:
- 按标点 `\p{P}\p{Z}\p{N}` 切段
- 每段内 char-level 扫描: 起始字命中 SURNAMES 表 (100+ 常见姓) → 取 3 字 (单姓双字名主流) → skip 3 步
- 字符位替换生成 variant: 「李福强」i=1「福」swap to「富」→「李富强」在 summary 里 → 记录 pair

**踩坑记录**:
1. ❌ regex `[\u4e00-\u9fa5]{3,4}` greedy 4-char: "李福强持枪" 把 "李福强" 吃成 "李福强持"
2. ❌ `(?<![<]ch[>])` look-around: Rust `regex` crate **不支持 lookbehind**
3. ❌ 字符边界 (prev/next 都是中文): 中文无空格, 永远被拒
**最终方案**: char-level manual scan, 完全绕过 regex 边界问题

**detect_role_confusion()** — 3 模式:
- 括号标注证人 → 看是否被错放在「辩护人」段
- 亲属辩护 → 「XX 的姐姐」不该出现在辩护人字段
- 辩护人段标题下出现证人亲属

**detect_fabricated_verdict()** — 区分「宣判」vs「择期宣判 / 未宣判」:
- `PENDING_PHRASES = ["择期宣判", "将择期宣判", "未宣判", "尚未宣判", "今日未宣判"]`
- transcript 含这些时不视为已宣判
- 检测 7 类判决表述: 判处 / 判决 / 决定 / 一审 / 二审 / 维持 / 改判

**highlight_unexpected_facts()** 扩展: 标黄变体名 + 判决词 (==⚠️⚠️==)

**is_safe() / issue_count() / needs_review() 同步扩展 3 字段**

**7 个新单测** (拿用户截图实际场景) — 全部 PASS
