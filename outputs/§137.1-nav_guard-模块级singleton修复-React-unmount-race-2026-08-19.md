# §137.1 nav_guard 模块级 singleton 修复 — React unmount race 导致 dialog 不弹

**binary**: target/release/meetily 70M mtime 11:30+

## 1. 根因 (race condition)

### 事件时序
1. 用户在 meeting-details 页点"生成摘要"
2. `useSummaryGeneration` → `setSummaryStatus('processing')`
3. `isSummaryInProgress = true` → `useNavigationGuard` useEffect 跑
4. useEffect 注册 `pushState` wrapper + `setPendingNav` setter
5. 用户点 Sidebar 链接 (e.g. "会议脉络" / "返回工作台")
6. Next.js `router.push('/knowledge')` 内部异步调用 `history.pushState`
7. pushState wrapper 拦截 → `pendingArgsRef.current = args; setPendingNav({to: '/knowledge', type: 'push'})`
8. **同步**: Next.js 拿到 fetch 响应,准备 unmount meeting-details + mount KnowledgePage
9. **React commit phase**:
   - meeting-details unmount → **useEffect cleanup 跑** → `window.history.pushState = originalPush`
   - setPendingNav 排队的 state 更新**被丢弃** (component 已 unmount)
10. KnowledgePage 渲染,URL 已经是 /knowledge (因为 Next.js 在 step 6 内部已记录路由意图)
11. **dialog 永远不弹**

### 为什么 §137 旧版不工作
- `useEffect` 注册 wrapper + state 都是 React lifecycle 内
- 路由切换时 meeting-details 立即 unmount
- cleanup 还原 pushState 早于 setState commit
- React 18+ concurrent 模式下 setState 可以被丢弃

---

## 2. 修复方案 — Module-level singleton + 引用计数

### 核心思路
- `pushState` / `replaceState` 包装移到 module-level,跨 component lifecycle 保持
- `pendingNav` 状态用 module-level + 订阅者 (subscribers Set)
- 引用计数管理 wrapper 生命周期:
  - 第一个 hook `when=true` 触发 acquire → 安装 wrapper
  - 最后一个 hook `when=false` 触发 release → 卸载 wrapper
  - **有 pending nav 时不卸载** (防止 dialog 在 unmount 后无法响 confirm)
- 每个 hook 通过订阅者模式同步 module-level state 到本地 React state

### 关键代码 (frontend/src/hooks/useNavigationGuard.ts)
```typescript
// module-level singleton
let wrapperInstalled = false;
let originalPush: typeof window.history.pushState | null = null;
let refCount = 0;
let currentPendingNav: PendingNav | null = null;
let pendingArgs: Parameters<typeof window.history.pushState> | null = null;
const subscribers = new Set<Subscriber>();

const acquireWrapper = () => {
  refCount += 1;
  if (refCount === 1) installWrapper();
};
const releaseWrapper = () => {
  refCount = Math.max(0, refCount - 1);
  // 关键: 有 pending nav 时保留 wrapper, dialog 才能在 unmount 后响 confirm
  if (refCount === 0 && currentPendingNav === null) uninstallWrapper();
};
```
