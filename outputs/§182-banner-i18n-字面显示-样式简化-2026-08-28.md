## 根因 (2 个)

### Bug 1 — 6 个 banner i18n key 全部缺失

`frontend/src/components/AISummary/NumberGuardBanner.tsx` 用 `t('summary.number_guard_182.banner_title')`, 但 zh.ts / en.ts 的 `summary.*` 块下**根本没这 key**:
- `summary.number_guard_182.*` (4 个 key)
- `summary.template_mismatch_182.*`
- `summary.pending_filter_182.*`
- `summary.timeline_conflict_182.*`
- `summary.party_role_183.*`
- `summary.timeline_coverage_183.*`

i18next 的 `t()` 对 missing key 默认**返回 key 字面字符串** (truthy), 所以 `t('...') || 'fallback'` 永远走 key 字面。

之前 zh.ts 实际只有 `summary.fact_guard` 和 `summary.fact_guard_148` 这两个 banner 的 key, 其他 6 个 banner 都缺 key。

### Bug 2 — 样式太丑太啰嗦

- 3 段叠加 (title + label + hint), 配色还行但:
- emoji ⚠️💡 太多
- padding 14px / fontSize 13px / margin 12px 偏大
- `<ul><li>` 列表 1 个数字一个 li 浪费空间

## 教训 (§56 + §107 强化)

1. **i18n key 缺失检测缺位**: `check_historical_fixes.py` 之前只 grep 文字锚点, 不验证 i18n key 路径实际可用
2. **`t('...') || 'fallback'` 是反模式**: i18next missing key 返 key 字符串 (truthy), fallback 永远不触发。改: 用 `t('...', { defaultValue: 'fallback' })` 或 `i18n.exists()` 预检查
3. **i18n lookup 完整性需 GUI 验收**: 任何新增 banner 必须实测一次, 不能 tsc + next build 蒙混 (§15)
