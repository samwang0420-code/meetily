**§190 commit 漏了向后兼容** — 用户老 settings 引用不存在的 model 名, 直接 hard Err 毙掉整流程。

### 修复 2: 未知 model 软 fallback

`frontend/src-tauri/src/summary/summary_engine/client.rs:171`:

```rust
// §190.1: Fallback to default model when settings reference an unknown model.
let model_def = match models::get_model_by_name(model_name) {
    Some(def) => def,
    None => {
        let fallback = models::get_default_model();
        log::warn!(
            "§190.1 fallback: model '{}' not in registry, falling back to '{}'. \
             User should re-select a model in Settings → Summary Model.",
            model_name,
            fallback.name
        );
        fallback
    }
};
let resolved_model_name = model_def.name.as_str();
// ... get_cached_model_path(app_data_dir, resolved_model_name)? ...
```

**之前**: `ok_or_else(|| anyhow!("Unknown model: ..."))?` → 整 chunk 流程毙掉
**现在**: warn + 用 `get_default_model()` (qwen2.5:3b) fallback → 流程继续 → 用户能拿到摘要 (只是用了 fallback model)

## 教训 (强化 §56 §92 §151)

1. **修改 model 列表是 breaking change for users**: 不能"代码里删 model 名"就完事, 用户 settings 里那个名立刻变 unknown
2. **新模型加入 → 旧模型进 legacy (不删)**: §190 是错误示范, §190.1 修正
3. **get_model_by_name 返 None 不能 hard Err**: 必须软 fallback (log warn + 用默认), 否则用户整流程毙掉
4. **§18 + §151 + §92 三铁律同时遵守**: 单一仓库 (§151) + 防代码漏 (§92) + AGENTS.md 双校 (§56)
