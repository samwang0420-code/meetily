# §98 identifier 改造后启动闪退三件套修复 (2026-08-10)

**Commit**: `32c7fd8` on `perf/summary-map-concurrency`

## 触发

用户报告 §97 identifier 改造后 `open '言镜 AI.app'` 启动 app 提示"意外退出"。根因排查发现 **3 个 bug 叠加**：

### Bug 1 — Info.plist CFBundleIdentifier 没跟上 identifier 改造
- `target/release/言镜 AI.app/Contents/Info.plist` 的 `CFBundleIdentifier` 仍是 `cn.lixianhuiji.app`
- 但 binary 内的代码已经全部用 `tech.yanjingai.app`（§97 commit 276906e）
- macOS LaunchServices 按 Info.plist identifier 加载 sandbox/entitlements/钥匙串，跟 binary 不匹配 → 拒绝启动

### Bug 2 — sqlx `_sqlx_migrations.checksum` 不匹配
- 用户机器新目录 `tech.yanjingai.app/meeting_minutes.sqlite` 是 8/7 旧的（缺 4 个 8/6 + 8/7 的 migration）
- 新 binary 的 migration 文件 hash vs db 记录不一致（3 个 migration 被改过注释/字段）
- sqlx 启动 panic：`migration 20260709000000 was previously applied but has been modified`
- 这跟 §73 同类 — sqlx "modified" 不是 missing，是 checksum mismatch

### Bug 3 — codesign identifier 跟 Info.plist 不一致
- 即使修了 Bug 1 和 Bug 2，新 binary 启动仍然 launchd 162 "Launch failed"
- 根因：`cargo build --release` 不重新签名 `.app` bundle
- binary 内 `Identifier=meetily-f4d07fa731b148b3` (cargo 嵌入的旧 codesign id)
- Info.plist `CFBundleIdentifier=tech.yanjingai.app` (sync 改过的)
- 这两个 id 必须一致 — macOS 拒绝不匹配的 bundle

## 修复（commit 32c7fd8）

### 1. `scripts/sync_app_bundle.sh` 加 §97 + §98 段

**§97 Info.plist 同步**（每次 sync 自动检测并改）：
```bash
EXPECTED_ID=$(plutil -extract identifier raw "$TAURI_CONF" 2>/dev/null)
PLIST_ID=$(plutil -extract CFBundleIdentifier raw "$APP_DIR/Contents/Info.plist")
if [[ "$PLIST_ID" != "$EXPECTED_ID" ]]; then
    sed -i.bak -E "s|<string>$PLIST_ID</string>|<string>$EXPECTED_ID</string>|" "$APP_DIR/Contents/Info.plist"
    plutil -lint "$APP_DIR/Contents/Info.plist"
fi
```

**§98 codesign 重签**（每次 sync 都验证 codesign id）：
```bash
CURRENT_BIN_ID=$(codesign -dv "$APP_DIR" 2>&1 | awk -F= '/^Identifier/ {print $2; exit}')
if [[ "$CURRENT_BIN_ID" != "$EXPECTED_ID" ]]; then
    codesign --remove-signature "$DST_BINARY" 2>/dev/null
    codesign --force --deep --sign - "$APP_DIR"
fi
```

### 2. `frontend/src-tauri/src/database/manager.rs` 加 startup 自愈

```rust
// §98 (2026-08-10): 启动前自愈 sqlx migration checksum mismatch.
if let Err(e) = Self::sync_migration_checksums(&pool).await {
    log::warn!("§98 sync_migration_checksums failed (best-effort, sqlx will report): {}", e);
}
sqlx::migrate!("./migrations").run(&pool).await?;
```

`sync_migration_checksums` 函数：
```rust
let migrations = sqlx::migrate!("./migrations");
for migration in migrations.iter() {
    let checksum = migration.checksum.as_ref();  // 直接用 sqlx macro 已算好的 SHA-384
    let row: Option<(Vec<u8>,)> = sqlx::query_as(
        "SELECT checksum FROM _sqlx_migrations WHERE version = ?1"
    ).bind(migration.version).fetch_optional(pool).await?;
    match row {
        None => { /* missing — sqlx 会自动跑 */ }
        Some((existing,)) if existing.as_slice() == checksum => { /* OK */ }
        Some(_) => {
            sqlx::query("UPDATE _sqlx_migrations SET checksum = ?1 WHERE version = ?2")
                .bind(checksum).bind(migration.version).execute(pool).await?;
        }
    }
}
```

**关键设计**：
- 用 `migration.checksum` (sqlx macro 已算好的 SHA-384 raw bytes)，不自己重算 hash（避免算法不一致）
- 失败仅 warn，不阻塞启动（best-effort，符合 §97 立铁律）
- 如果 db 缺某 version 行，不预创建（让 sqlx::migrate! 后续自动跑）
