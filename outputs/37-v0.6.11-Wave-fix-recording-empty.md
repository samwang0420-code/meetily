# v0.6.11 · 修复最近两条会议识别为空

**Binary**: PID 27351 (16:24 build, npm 10s + cargo 1m24s)

## 用户反馈
"最近的两条会议记录, 完全没识别出来内容"

## 根因诊断

### 数据库 + 录音夹双重检查
- **Meeting 1 (15:59, 40 秒)**: SQLite `transcripts` 表只有 `万 。` 和 `.` 两个噪音片段
- **Meeting 2 (16:09, 17 秒)**: SQLite `transcripts` 表**全空** (`segments = []`)

### 核心 Bug: v0.6.11 streaming pipeline 切换

之前 worker.rs sherpa branch 改成 streaming:
- partial emit `transcript-partial` (灰色预览, **不存**)
- **只有 `is_endpoint + delta` 才 emit `transcript-update` (最终段, 落库)**

但 silence detector 阈值 **-45dB + 1200ms 连续静音**：
- 会议连续说话时, **从未触发 is_endpoint**, buffer 一直累积
- 录音停止时 finalize 调用 → daemon 重置时把累积 30+ 秒音频识别成一句话
- → meeting 1 = "万 。"  (整 30+ 秒判成一句)
- → meeting 2 = "" (buffer 在 finalize 时被 sensevoice 判定为空信号)

### Bug 2: useRecordingStop retranscription 触发条件
```ts
if (folderPath && freshTranscripts.length > 0) {
  invoke('start_retranscription_command', ...)  // 整段重解析
}
```
- 要求 `freshTranscripts.length > 0`, 但 freshTranscripts 来源是 `transcript-update`
- meeting 2 = 0 条 → retranscription **跳过** → meeting 2 永久空白
- 这是兜底逻辑的兜底 bug, 严重

## 修复

### 1. useRecordingStop.ts:344 - 关键 fix
- `if (folderPath && freshTranscripts.length > 0)` → **`if (folderPath)`**
- 只要 audio.mp4 落盘, 就触发 retranscription 整段重解析
- 失败不阻塞主流程

### 2. 立即修复最近两条会议

直接调用 sherpa daemon `transcribe` (整段 + SenseVoice 全序列 + Paraformer 备选):
- **Meeting 1 (15:59, 40s)**:
  - Paraformer: `每天金三十万将是什么样的条件`
  - SenseVoice: `北京3万。`
  - 用 Paraformer 输出写入 transcripts (前 4 秒是真实语音, 后 35 秒静音)
- **Meeting 2 (16:09, 17s)**:
  - SenseVoice: `你好，我是王威。呃，今天我们开会的内容呃都有什么呢？大家都说一下。` ✓
  - SQL update + transcripts.json 双写

### 3. 数据库同步
- `transcripts` 表用 sqlite3 直接 UPDATE
- `transcripts.json` 文件用 SenseVoice 整段识别结果写回
- metadata.json 加 `retranscribed_at + retranscribed_by`

## 已知边界 (建议下一轮)

1. **Silence detector** `-45dB + 1200ms` 太严格 — 长会议连续说话无静音时整段无 final
   - 建议: 增加 **buffer 累计 ≥ 30s 强制 endpoint** 逻辑
2. **stream_finalize** 不会自动把累积 buffer 跑完 — 录音结束 streaming finalize 应该跑一次累积 buffer 整段识别
3. **录音中持续小声 / 数据 spike** 未识别 (meeting 1 整段只有前 4 秒语音)
4. **SenseVoice + Paraformer 双模型差异** 用户没感知, 可后续让用户选模型决定输出
