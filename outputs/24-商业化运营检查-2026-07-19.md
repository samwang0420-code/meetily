- **修复前**: 0 个退款命令, 客服只能手工改 DB
- **本轮新增 6 个 admin 命令** (全部 operator_token 鉴权):
  - `admin_list_users` — 列出用户清单 (id, email, membership, machine_id, month_used, is_active)
  - `admin_revoke_membership` — 撤销会员 (membership='free', 清 license_key)
  - `admin_unbind_machine` — 解绑机器 (machine_id=NULL, 会员保留)
  - `admin_set_user_active` — 封号 / 解封 (is_active=0/1)
  - `admin_reset_user_quota` — 重置本月配额
  - `admin_refund_user` — 一键退款 (撤销会员 + 解绑机器)

### E. 分析 / 计数 ❌ **完全 stub** (P1 修复)
- 修复前: `analytics::commands` 全是 `Ok(())` / `false`, 25 个事件无脑丢
- **本轮新增**: `analytics_events` 表 (id, user_id, event_name, properties_json, created_at) + 2 个索引
- 改写 25 个 tauri command, 全部写本地 SQLite
- `is_analytics_enabled` 改回 `true` (因为本地了, 0 隐私风险)
- 失败静默 (`write_event` 内 `let _ = ...`, 不阻塞主流程)

### F. 错误监控 / Sentry ❌ **零监控** (P2 修复)
- 修复前: 无 Sentry / Bugsnag / Crashlytics
- **本轮新增**: `install_panic_hook()` 在 `run()` 启动时注册
  - 任何 Rust 线程 panic → 调默认 hook (stderr + log) + 写 `$APP_DATA_DIR/crashes/crash-YYYYMMDD-HHMMSS.txt`
  - 包含 timestamp / version / os / arch / panic_info / backtrace
  - 自动清理只保留最近 50 个 crash 文件
- 完全本地, 0 网络
