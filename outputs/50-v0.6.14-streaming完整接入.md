## 关键设计

### 1. feature flag 默认关闭
```rust
pub fn streaming_enabled() -> bool {
    std::env::var("OFFLINE_HUIJI_STREAMING")
        .map(|v| v == "1" || v.to_lowercase() == "true")
        .unwrap_or(false)  // ← 默认 false
}
```
- 7/12 事故就是因为默认 streaming 路径 bug
- **保守起见**:不开 flag = 完全等价 v0.6.13(走原 transcribe_blocking)
- 开启:`OFFLINE_HUIJI_STREAMING=true open /path/to/meetily`

### 2. session 生命周期
```
录音开始 (start_transcription_task 入口):
  ↓
  if streaming_enabled() && engine is Sherpa:
    SherpaStreamSession::begin(model)  →  session Arc<Mutex<...>>
    emit("streaming-session-started")
  else:
    streaming_session = None
  ↓
每个 chunk:
  ↓
  transcribe_chunk_with_provider(..., streaming_session.clone())
  ↓
  if Some(session):
    push(audio)  →  { partial, delta, is_endpoint }
    if partial:  emit("streaming-partial", {chunk_id, text, is_partial: true})
    if delta:    return (delta, 0.85, false)  // 当 final emit transcript-update
  else:
    原 transcribe_blocking 路径(完全不变)
  ↓
worker 全部退出:
  ↓
  if Some(session):
    等 workers 释放 Arc clone (≤5s, 轮询 strong_count)
    session.finalize()  →  emit("transcript-update") (残留 delta)
    emit("streaming-session-ended")
```

### 3. 失败回退(自动)
- `stream_begin` 失败 → `streaming_session = None` → 走 blocking
- `stream_chunk` 失败 → warn + 走 blocking
- **任何 streaming 错误不影响录音主流程**

### 4. 全局 session 唯一性
```rust
static SESSION_MAP: Lazy<Mutex<HashMap<String, SessionMeta>>>  // 防 7/12 重蹈
```
- 多 worker 不能各自建 session
- `list_active_sessions()` / `cleanup_all_sessions()` 诊断

## 端到端实测(Python daemon 模拟)

脚本 `/tmp/test_worker_stream_simulation.py` 模拟 worker 实际行为:

| 阶段 | 时长 | 行为 |
|---|---|---|
| `stream_begin` | 52ms | 起 session,加载 sensevoice-zh |
| **chunk 1** (3.9s 音频) | **822ms** | 返 partial+delta, emit 2 个事件 |
| chunk 2 (3.4s) | 2ms | 没新输出(等静音 endpoint) |
| chunk 3 (3.3s) | 1ms | 同上 |
| `stream_finalize` | **151ms** | 残留 delta, emit 1 个 transcript-update |
| **总计** | 999ms | **4 个 emit 事件** |

### emit 事件(给前端用)
```js
1. streaming-partial: { chunk_id, text: "今天...", is_partial: true }   // 灰色预览
2. transcript-update: { chunk_id, text: "今天...", is_partial: false }  // final 段
3. transcript-update: { chunk_id: "finalize", text: "完整 3 句合并" }
4. streaming-session-ended: { session_id, segments_emitted: 1 }
```

### 对比 blocking 模式
- 同一段 3.9s 音频,blocking 73ms 出整段
- streaming 模式 822ms 出第 1 句 partial,**用户早 5-10 秒看到文字**

## 边界 / 已知

- **chunk2/3 没新输出**: 等静音 endpoint 才出 final, **不是 bug**,daemon 协议设计如此。如果想强制,Python daemon 有 `force_final_ms=30000` 默认 30s 强制 emit。
- **前端 UI 暂未渲染 partial**: emit 事件已发,但 `TranscriptView` 没监听 `streaming-partial`。前端要加 5 行代码就接上。
- **Apple Silicon 编译警告 14 个**: 全是无关 dead code,不动。
- **NUM_WORKERS=1**: serial 模式,后续多 worker 需要 stream session 加锁(7/12 报告 #2 候选)。
