# §129 重新生成摘要报错修复 (2026-08-17)

## 触发

用户 2026-08-17 上午截图反馈: "重新生成摘要报错", 显示:

> 生成总结出错
> Summary generation timed out after 15 minutes. Please try again or check your model configuration.

影响:
- 1 个 summary_processes 行卡 PENDING (`meeting-566fe7a9`, 537 段 / 26k chars / 106 min 音频)
- DB PENDING 行从 8/16 05:30 一直持续到 8/17 01:04, **永远不会清**

## 根因 (3 条叠加)

### 1. 前端 polling MAX_POLLS=300 (10 min) 太短

`frontend/src/components/Sidebar/SidebarProvider.tsx:201`:
```ts
const MAX_POLLS = 300; // 10 minutes at 2-second intervals
```

但实际后端 Map-Reduce 经常超过 10 min:
- 二郎神会议 (35 min / 268 段): 5 chunks × 1,072s = **17.9 min** (超 MAX_POLLS)
- 宇宙演化 (106 min / 828 段): 10 chunks × 565s = 9.4 min (贴近)
- 当前卡住的 566fe7a9 (106 min / 537 段): 预估 12-15 min (必超)

### 2. 错误消息硬编码 "15 minutes" 但实际是 10 min

```ts
error: 'Summary generation timed out after 15 minutes. ...'
```

用户看到的"15 分钟"实际是"10 分钟"。文案和数据不匹配 (跟 §107 录音通知 toast 同病)。

### 3. DB 陈旧 PENDING 行永不清理

`api_process_transcript` → `SummaryProcessesRepository::create_or_reset_process` 设 status='PENDING'
正常流程:
- PENDING → completed (成功) / failed (失败) / cancelled (取消)
- 异常流程 (force-quit / OOM / llama-helper crash): **永远 PENDING**

重启 app 不会清理这些行, 一直累积. 每次重新生成都看到老的 PENDING 行.

## 修复 (3 文件 + 1 doc)

### 1. `frontend/src/components/Sidebar/SidebarProvider.tsx`
- `MAX_POLLS = 300` → **`MAX_POLLS = 900`** (30 min at 2s interval)
- 加 `localT(path)` helper (跟 §104.1 录音通知 toast 同模式, utility function 不能用 useTranslation)
- 超时后**兜底再查一次** backend, 万一在这期间已完成 → 显示成功, 不显示"失败"
- 错误消息走 i18n: `localT('summary.timeout_error').replace('{minutes}', '30')`

### 2. `frontend/src/i18n/locales/{zh,en}.ts`
- 新增 `summary.timeout_error` zh + en key, `{minutes}` 占位符

### 3. `frontend/src-tauri/src/database/repositories/summary.rs`
- 新增 `cleanup_stale_pending_processes(pool, stale_minutes)` 函数
- SQL: `UPDATE summary_processes SET status='failed', error='Interrupted by app shutdown — ...', result=COALESCE(result_backup, result) WHERE status='PENDING' AND updated_at < ?`
- 保留 result_backup 恢复 (跟 §P1-B 一致)

### 4. `frontend/src-tauri/src/lib.rs`
- 启动钩子 (database::setup 之后, 后于 §99.2 backfill spawn):
  ```rust
  tauri::async_runtime::spawn(async move {
      if let Some(app_state) = app_for_cleanup.try_state::<crate::state::AppState>() {
          let pool = app_state.db_manager.pool();
          match database::repositories::summary::SummaryProcessesRepository::
              cleanup_stale_pending_processes(pool, 30).await { ... }
      }
  });
  ```
- 阈值 30 min = MAX_POLLS 上限, 比 polling 多给点 buffer
- 必须用 `tauri::async_runtime::spawn` (跟 §99.5 一致, 不用 tokio::spawn)
