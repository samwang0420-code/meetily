## 现状与机器要求 (你问了)

> 用户原话: "实事求是的告诉我目前我们对于录音和总结都支持多少时间的会议, 对于机器的要求是什么, 你是如何实现的, 卡点是什么"

### 录音时长支持

| Tier | 触发条件 | 录音上限 | ASR 默认 | diar | 长摘要 |
|---|---|---|---|---|---|
| **High** | ≥16GB + Apple Silicon (M1/M2/M3/M4) | **90 min** | FunASR-Nano | cam++ 开 | Map-Reduce 1800/50 开 |
| **Medium** | ≥8GB | **90 min** | SenseVoice-zh | cam++ 关 (省内存) | 同上 |
| **Low** | <8GB | **30 min** | SenseVoice-zh | cam++ 关 | 长摘要禁 (token 限制) |

### 内存阈值降级

- 全局进程 RSS > **1.2 GB** 触发 `is_memory_pressure(rss_mb)`
- 前端 `HardwareStatusBadge` 顶部红色提示 "内存压力,已自动降级"
- 建议自动卸载 cam++ / FunASR-Nano, 仅保留 SenseVoice
- 阈值常量 `hardware::MEMORY_PRESSURE_THRESHOLD_MB = 1200`

### 机器要求

- **最低**: 8GB RAM (medium tier, 90min 纯转写)
- **推荐**: 16GB+ Apple Silicon M 系列 (high tier, 90min 全功能 + 高精度)
- **不推荐**: <8GB (low tier, 30min 短录音, 摘要简化)

### 实现路径

1. **检测** (`hardware/mod.rs::DeviceProfile::detect()`)
   - `sysinfo::System::new_all().refresh_memory()` 拿总 RAM
   - CPU 品牌 `cpus().first().brand()` (Apple Silicon 检测 `"Apple M"`)
   - Metal VRAM (macOS only) ≈ 系统 RAM × 60% (UMA 共享显存)
2. **分级** (`match total_memory_gb` + `is_apple_silicon`)
   - ≥16GB + M 系列 → High
   - ≥8GB → Medium
   - <8GB → Low
3. **降级策略** 静态编译期决定 (`recommended_asr_model`, `cam_plus_plus_disabled` 等布尔位)
4. **运行时监测** 30s 轮询 RSS, 超过 1.2GB 触发 `hardware-pressure` 状态

### 卡点 (你的"300s 大坑"问题)

**老架构**: 长会议 diar 后台串行阻塞 → 16-30 分钟才能算完 → 期间 transcripts.speaker 永久空白。
- 单轮跑 60min+ 会议, 会议结束后 user 看不到 speaker 标签 → 用户挫败
- 即使重启 app 也无法补救 (diar 结果已丢失)

**新架构**: 双保险
1. **即时回填**: `save_transcript` 触发 `apply_diar_pickup_to_meeting(meeting_id, archive=true)`, 把已处理的 json rename 到 `.applied.{ts}.json`
2. **兜底回填**: `diar_pickup_loop::spawn_diar_pickup_loop(app)` 30s 循环扫 `/tmp/lixianhuiji_diar/*.json`, 处理后归档 + emit `transcripts-updated` 事件 → 前端 useEffect 自动 refetch

**已知遗留 (P2)**: diar 本身仍单进程串行。P0-2 只解决"speaker 标签不丢", **diar 计算耗时本身没缩短**。要 90 分钟录音后 16 分钟拿到 speaker, 用户耐心等。P1 列了"Diar 单进程串行排队阻塞新会议", 内测后再做。

## 录音 + 摘要技术栈

| 层 | 技术 | 说明 |

| 摘要 reduction | `recursive_reduce_summaries` depth=5 | P0-1 新增 |
| 模板 | legal / medical / generic 通用 | 摘要结构化 |

## 1 小时真人录音验收 (阻塞内测)

**必须用户在真 GUI session 完成, CLI 测不出**:

1. **重启 app** (launchd GUI session)
2. **录音 60 分钟** (真人谈话或读文档)
3. **结束后检查**:
   - DB 中 transcripts 表段数 ≥ 1
   - speaker 标签在 16-30 分钟内陆续回填 (定时 loop 兜底)
   - 触发 Map-Reduce 摘要生成, UI 展示 "分块总结处理中 / 合并分块结果中 / 生成全局结构化纪要"
   - 摘要字数 ≤ 1200 token (`clamp_max_tokens`)
4. **硬件检查**: 顶部 badge 显示档位 + RSS, 1.2GB 阈值告警正常
5. **自助激活**: 登录 → /redeem → 输入测试激活码 → 升级 Pro
6. **内存观测**: 全程无 OOM / 无闪退 / DB 无数据丢失
