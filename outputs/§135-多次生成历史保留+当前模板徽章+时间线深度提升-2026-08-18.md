# §135 多次生成历史保留 + 当前模板徽章 + 时间线深度提升 (2026-08-18)

## 触发

用户 8/18 反馈 4 个独立痛点:
1. **90+ min 庭审 (911f52ae)**: 模板 `court_hearing` 生成 30 段抽象输出, 跟央视节目 1 分钟简介密集事实陈述差距巨大
2. **模板选错**: 用户不知道自己选了哪个模板, 花了 10+ 分钟生成后才发现, 浪费
3. **多次生成历史丢失**: 第 1 次生成 court_hearing, 第 2 次 standard, 第 3 次 legal — 旧版本全部消失
4. **不同模板差异不可比**: 用户不知道 5 模板对同一会议输出到底有什么不同

## 4 项修复 (10+ 文件)

### A. 后端 — 多次生成历史保留

- **新表 `summary_history`** (`migrations/20260818000000_summary_history.sql`):
  - meeting_id, template_id, template_name, model_name, chunk_count, processing_time
  - result_json (完整 result 含 markdown + fact_guard)
  - created_at (旧版本原时间) + archived_at (归档时间)
  - backup_reason ('regenerate' | 'template_switch' | 'manual_backup')
  - 索引: (meeting_id, archived_at DESC), (template_id)
- **`create_or_reset_process` 改**: 备份到 result_backup (失败回滚) **同时** INSERT INTO summary_history (永久保留)
- **新 Tauri commands** (`summary/commands.rs`):
  - `api_summary_history(meeting_id)` — 拉该会议所有历史
  - `api_summary_current(meeting_id)` — 拉当前 summary_processes.result
  - `api_summary_history_get(history_id)` — 拉某条历史 result_json

### B. 后端 — 模板 prompt 时间线深度提升

- **新全局规则 `§135 TIMELINE EXTRACTION RULE`** (`processor.rs:67`):
  - "EXTRACT SPECIFIC EVENTS, NOT ABSTRACT SUMMARIES"
  - 每事件: 时间 (verbatim 年/月/日) + 主体 (verbatim 人名) + 行为 (具体动词) + 数字 (verbatim 金额数量单位) + 结果 (判决/裁定)
  - **最少 5 条, 90+ min ≥ 10 条**
  - 央视 2012/2020/2021/2022.5 庭审示例直接嵌入 prompt
- **新规则 `ANTI-ABSTRACT RULE`**: 禁用 "本次会议讨论了" / "涉及" / "相关内容" / "未提及" 作主体
- **4 主模板加 "事实时间线" 段** (作为 sections[0]):
  - standard_meeting / court_hearing / legal_consultation / medical_consultation
  - instruction 强制 ≥ 5 条具体事件 + 引用原文措辞 + [证据: mm:ss] 时间戳
- **3 个新 test** (processor.rs + templates/defaults.rs):
  - `evidence_rules_cover_timeline_extraction_rule` — 验证 prompt 包含 2 个新规则
  - `test_four_main_templates_have_key_events_timeline` — 验证 4 主模板有时间线段

### C. 前端 — 当前模板徽章

## 用户体验流程 (修复后)

1. 用户选模板 **A** → 紫色徽章显示"当前模板: A"
2. 生成 5-15 min → 摘要完成
3. 用户想换模板 **B** 试 → 选 B → 再生成 5-15 min
4. **关键**: 此时 **A** 的摘要自动存到 `summary_history` 表, 永久保留
5. 用户点顶部"历史摘要"按钮 → 弹窗列出 A 和 B 两条
6. 选 2 条 → 顶部出对比卡片 (并排 markdown preview)
7. 用户点 A 的"查看" → 回到主区显示 A 摘要 (B 也还在, 没被覆盖)
8. 用户对比后发现 B 更好 → 主区是 B (从 history 切回 current 也行)
