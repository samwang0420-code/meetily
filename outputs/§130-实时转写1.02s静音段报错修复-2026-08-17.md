# §130 实时转写 1.02s 静音段报错修复 (2026-08-17)

## 触发

用户 2026-08-17 上午录制 CCTV 庭审视频 (北京市第三中级人民法院走私运输毒品案公开审理直播报告, 34分钟 / 102 段 / 27 个 ≤2s 短段), 反馈:

> 录制一段时间后有红色 toast 报错: `Transcription failed: sherpa slot 0 error: paraformer-zh returned empty transcript for 1.02s audio`

但实际录音正常 (DB 有 102 段转写), 错误 toast 持续弹。

## 根因 (3 层)

### 1. Python sherpa_asr.py:1078 raise 过于激进

```python
if not raw_text and len(arr) / sr >= 1.0:
    raise RuntimeError(f"{loaded_tag} returned empty transcript for {len(arr)/sr:.2f}s audio")
```

§30 硬化 (2026-07-29) 立时是为了防止"未注册模型静默 fallback", 但这一行 raise 把 **所有 ≥1.0s 空文本** 都视为错误, 包括 VAD 静音段 (用户机器 paraformer-zh 不能解码纯静音 → 返空文本 → raise)。

实际数据: 102 段中有 27 段 (26%) 是 ≤2s VAD 静音切出, 这些都是 raise 假阳性。

### 2. Rust worker.rs 不区分空段和真错误

```rust
Err(e) => {
    error!("Sherpa transcription failed for chunk {}: {}", chunk.chunk_id, e);
    let _ = app.emit("transcription-error", &serde_json::json!({...}));
    Err(e)  // 所有错误一律上抛
}
```

任何 Err 都发 `transcription-error` 事件, 不区分"空段" vs "真模型加载失败"。

### 3. 前端 RecordingControls 无条件停录音

```typescript
setTranscriptionErrors(prev => prev + 1);
setIsProcessing(false);
onRecordingStop(false);  // 任何 transcription-error 都停录音
```

后果: 第一次 transcription-error 触发后:
- `isRecording = false` (UI 显示"已停止")
- 但 Rust 实际音频录制继续 (DB 仍然在写 102 段)
- 用户看到 UI 状态不一致 + 红色 toast 假警报

## 修复 (3 文件)

### 1. `frontend/src-tauri/scripts/sherpa_asr.py`

- 提到模块级 `SILENCE_DB = -45.0` (原是 streaming partial 函数局部变量)
- raise 改为只针对 ≥2.5s 非静音音频:
  ```python
  audio_seconds = len(arr) / sr
  if not raw_text and audio_seconds >= 2.5:
      rms = float(_np.sqrt(_np.mean(_np.square(arr.astype(_np.float32))) + 1e-12))
      db = 20.0 * _np.log10(rms + 1e-12)
      if db > SILENCE_DB:
          raise RuntimeError(f"{loaded_tag} returned empty transcript for {audio_seconds:.2f}s audio (rms={db:.1f}dB)")
      sys.stderr.write(f"[sherpa_asr] §130 silent segment skipped: {audio_seconds:.2f}s rms={db:.1f}dB (<={SILENCE_DB}dB)\n")
  ```
- < 2.5s 任何 RMS → silent skip, stderr warn
- ≥ 2.5s 低 RMS → silent skip (长静音)
- ≥ 2.5s 高 RMS → raise (真模型 bug, §30 硬化保留)

### 2. `frontend/src-tauri/src/audio/transcription/worker.rs`

- 区分空段 vs 真错误, 空段返 Ok 跳过:
  ```rust
  Err(e) => {
      let err_str = e.to_string();
      let is_empty_segment = err_str.contains("empty transcript for");
      if is_empty_segment {
          warn!("Worker: empty transcript for chunk {} ({}), treating as silent segment",
                chunk_id, err_str);
          return Ok((String::new(), None, false));
      }
      // 真错误才 emit transcription-error
      ...
  }
  ```

### 3. `frontend/src/components/RecordingControls.tsx`

- 只 actionable=true (模型加载失败需用户介入) 才停录音:
  ```typescript
  if (isActionable) {
      setIsProcessing(false);
      onRecordingStop(false);
  }
  ```
- 非 actionable (单段失败 / 短音频) → 仅累加错误计数 + 让 useModalState 弹 toast, 不动录音状态
