# 离线会记核心质量补救 v0.6.16

日期：2026-07-16

## 本轮目标

不再扩展模板和营销，先降低“错误转录导致错误纪要”的风险。实时转写继续作为草稿，纪要生成增加证据约束。

## 已完成

- 摘要短文本分块提示改为“证据台账”模式。
- 长文本分块合并提示保留原文 `[MM:SS]` 时间戳。
- 最终模板报告要求：
  - 只能使用原文明确出现的事实；
  - 人名、金额、日期、负责人、截止时间不能推测；
  - 提案不能改写成决定；
  - 没有负责人/截止时间时明确写未指定；
  - 模糊内容标记 `Needs confirmation`；
  - 关键结论和行动项尽量保留录音时间戳。
- 新增回归断言，防止后续重构删除这些约束。

## 验证

- 摘要处理器测试：`21 passed, 0 failed`。
- Rust `cargo check`：通过。
- 前端 `npm run build`：通过。

## 下一步质量验证

需要用同一批真实录音比较：

1. 当前实时转录结果；
2. 录音后重转写结果；
3. 两者生成的纪要；
4. 人工标注的真实事实。

至少准备三类样本：安静中文单人、多人会议、包含人名/金额/日期/专业术语的会议。每段只比较漏字、关键实体错误、行动项错误和纪要事实错误，不以“看起来通顺”作为通过标准。

## 商业化判断

本轮代码改动不能证明识别准确率已经达标。只有真实样本验证后，才能决定是否继续优化模型、音频前处理或转为“本地录音后高质量处理”定位。
