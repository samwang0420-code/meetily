# §131.4 缺失 5 模板注册到 defaults.rs (2026-08-17)

## 触发

用户 8/17 反馈: "你的这几个模板我在软件里面看不到啊" — §131.3 改的 5 个全英文模板
(standard/daily/project/retro/sales) + 之前的 cross_border_ecommerce + psychatric_session
在 app 模板选择里都看不到。

## 根因 (1 跳)

`frontend/src-tauri/templates/` 下有 **10 个 JSON 文件**, 但 `defaults.rs::get_builtin_templates()`
只注册了 5 个 (standard/daily/legal/medical/court_hearing), 缺 5 个:

| JSON 文件 | §131.4 注册常量 | 之前状态 |
|---|---|---|
| `cross_border_ecommerce.json` | `CROSS_BORDER_ECOMMERCE` | JSON 在, 常量无 |
| `project_sync.json` | `PROJECT_SYNC` | JSON 在, 常量无 |
| `retrospective.json` | `RETROSPECTIVE` | JSON 在, 常量无 |
| `sales_marketing_client_call.json` | `SALES_MARKETING_CLIENT_CALL` | JSON 在, 常量无 |
| `psychatric_session.json` (注: 文件名拼写错, 有 `c`) | `PSYCHIATRIC_SESSION` | JSON 在, 常量无 |

10 个 JSON 写好但只 embed 5 个, `include_str!` 只在 `pub const` 处生效, 没有常量
就完全没有字符串进入 binary, Rust 端 `get_builtin_template(id)` match 走 `_ => None`,
前端 `listTemplateIds` 拿不到这些 id, 用户选择器里看不到。

## 修复 (1 文件, +21 行)

`frontend/src-tauri/src/summary/templates/defaults.rs` 4 处同步:
1. 顶部 5 个新 `pub const ... = include_str!(...)`
2. `get_builtin_templates()` vec 加 5 个 (id, content) 元组
3. `get_builtin_template(id)` match 加 5 个 arm
4. `list_builtin_template_ids()` vec 加 5 个 id

## 教训 (§56 强化 + §131 系列)

§131.3 改完 5 个 JSON 后, **没有在 `defaults.rs` 注册**。这个 1 跳 bug 让用户实际
看不到任何"新模板" — 等于没改。

**新加铁律**:
1. 任何 `templates/*.json` 新增或重命名 → **必须同步改 `defaults.rs` 4 处** (常量 + get_builtin_templates + get_builtin_template + list_builtin_template_ids)
2. 改完必跑 `cargo build --release` + `grep kw binary` 验证字符串 embed
3. guard 锚点必须含 4 处 1:1, 不能只查一处
