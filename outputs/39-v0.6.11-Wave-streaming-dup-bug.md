## 用户反馈
"最近一条录音实时识别的内容: 同一个时间段出现了 2 次; 延时 1 分多钟才出现识别内容"

## 根因诊断

### SQL 证据
会议 `meeting-02c7f2d9-d8ef-42b8-9f70-c9fc8f730017` (Meeting 2026-07-10_16-47-04, 153.43s 录音)

`transcripts` 表实际 6 条, 但应该是 3 段 (force_final 30s 触发切句):
```
27.48 - 51.31s  (×2 完全相同)  ← 第 1 段
79.89 - 102.10s (×2 完全相同)  ← 第 2 段 (51+28=79)
131.25 - 153.43s (×2 完全相同) ← 第 3 段 (102+28=130)
```

3 段间隔 28s = `force_final_ms=30000` 触发点。

### transcripts.json 也确认
6 个 segment, 各自 sequence_id 0-5, 但 start_time/end_time/text 两两完全相同。

### Bug A 根因: 双重 transcript-update listener 泄漏

`frontend/src-tauri/src/audio/recording_commands.rs` `start_recording_with_devices_and_meeting` 函数**内部注册 2 个完全相同的 listener** (line 265 + line 436), 都 `app.listen("transcript-update", ...)`, 都调 `manager.add_transcript_segment(...)`。

**`TRANSCRIPT_LISTENER_ID` 是 `Mutex<Option<EventId>>`**, 第 2 个 listener 注册时**覆盖第 1 个 listener_id**, 所以 `stop_recording` 只能 unlisten 第 2 个, **第 1 个永远泄漏**。

每次录音泄漏 1 个 listener, 用户做了 6 次录音 → 累积 6 个 listener, 1 次 emit → 6 次 add → 6 个 segment 写进 transcripts.json + DB。

之前 `add_transcript_segment` 按 `sequence_id` 去重, 但 SEQUENCE_COUNTER 在 6 个 listener 闭包间持续增长 (各取不同 seq), 6 个不同 seq 全被加进 segments Vec, **去重失效**。

### Bug B 根因: 前端 `livePartialText` 没人消费

`frontend/src/contexts/TranscriptContext.tsx` 已维护 `livePartialText` + `isPartialEndpoint` 状态, onTranscriptPartial listener 持续 setLivePartialText。

但 `TranscriptView.tsx` 和 `VirtualizedTranscriptView.tsx` **两个组件都没调用 `useTranscripts()` 拿 livePartialText**。

结果: sherpa_asr.py 推 transcript-partial 事件 → Context 更新 state → **UI 不渲染**。用户从录音开始到 27.5s 第一段 final 出现的整段时间, 屏幕完全空白 (除了"正在聆听..."指示器)。

## 修复

### Fix 1: 删重复 listener (根本修复)
`frontend/src-tauri/src/audio/recording_commands.rs` 删除 line 260-290 整个 listener 块 (保留 line 431-456 那份), 注释说明:

```rust
// CRITICAL: Listen for transcript-update events (saving segment via add_transcript_segment).
// 仅在 start_recording_with_devices_and_meeting 末尾注册 1 次; 之前在中间注册了 1 次
// (TRANSCRIPT_LISTENER_ID 会被覆盖, stop_recording 时只能 unlisten 后者, 前者永远泄漏,
//  反复录音后多 listener 累积, 1 次 emit 触发 N 次 add → transcripts 重复段)
```

### Fix 2: add_transcript_segment 双层去重 (防御)
`frontend/src-tauri/src/audio/recording_saver.rs:96` 加 (audio_start_time, audio_end_time) 二次去重 (容差 50ms):

```rust
let dup_by_seq = segments.iter().position(|s| s.sequence_id == segment.sequence_id);
let dup_by_time = if dup_by_seq.is_none() {
    segments.iter().position(|s| {
        (s.audio_start_time - segment.audio_start_time).abs() < 0.05
            && (s.audio_end_time - segment.audio_end_time).abs() < 0.05
    })
} else { None };

if let Some(idx) = dup_by_seq {
    segments[idx] = segment.clone();  // update
} else if let Some(idx) = dup_by_time {
    warn!("DEDUP-time: skipping ...");
} else {
    segments.push(segment.clone());
}
```

即使将来 listener 再次注册重复, 时间范围相同 50ms 内的 emit 都会被吞掉, 不会再出现"6 段重复"。

### Fix 3: 前端渲染 livePartialText
`frontend/src/components/TranscriptView.tsx` + `VirtualizedTranscriptView.tsx`:

1. `import { useTranscripts } from '@/contexts/TranscriptContext';`
2. 组件内 `const { livePartialText, isPartialEndpoint } = useTranscripts();`
3. 在 transcripts 列表后、"正在聆听..." 指示器前, 渲染灰色 partial 块:
```tsx
{isRecording && !isStopping && !isPaused && !isProcessing && livePartialText && (
  <motion.div ... className="mb-3 ml-12">
    <p className="text-sm text-gray-400 italic leading-relaxed">
      {livePartialText}
      <span className="inline-block w-1.5 h-3.5 bg-gray-400 ml-0.5 align-middle animate-pulse" />
    </p>
    {isPartialEndpoint && <p className="text-xs text-gray-300 mt-1">正在切句...</p>}
  </motion.div>
)}
```

VirtualizedTranscriptView 有 2 个分支 (virtualized + simple), 两处都加。
