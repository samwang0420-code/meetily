## 根因

XHToken fork 的 spark2_5 kernel 是为 spark2_5 架构权重特化 (weight layout, dequantization pattern 都不一样), 反而**拖累 Qwen3.5 Q4_K decode path**:
- ggml_metal_graph_compute 调用次数下降
- ggml_gemv_q4_K_8x4_q8_K CPU fallback 上升
- Per-token decode 走 Metal Q4_K kernel 反而不命中

## 决策: Path C（暂停 §205.2）

**理由**:
1. XHToken fork 对 Spark 之外的模型（Qwen3.5）负优化
2. 没有现成 Spark-X2.5 Q4_K_M GGUF（F16 3.27GB 自量化要额外工程）
3. §197 已是 Apple Silicon Q4_K per-token decode 实测最优
4. **0.9.4 release 流水线不被冒险**
