# §199.5.1 strip_long_text_evidence_ids 索引错位 bug 修复 v3 (2026-08-31)

## 触发

观察 meeting-b0297a12 实际生成的摘要 result, 发现 `[证据: 二零一七年十一月十四日下午一时许]` / `[证据: 当天早晨]` / `[证据: 九时三十分许]` / `[证据: 二零一七年十月十四日]` / `[证据: 二零一八年五月十一日]` — **5 个非标 evidence ID 全部残留**, 应该被 strip 但实际没生效。

§199.5 guard anchor (`199_5_strip_long_text_evidence_ids_exists` + `199_5_service_wires_long_text_strip`) 都 pass, 但实际输出仍有中文时间戳作为 evidence ID。

## 根因 (v2 算法索引错位)

`hard_post_process.rs::strip_long_text_evidence_ids` v2 用 `format!` + `safe_slice` 倒序删除:

```rust
let mut to_remove: Vec<(usize, usize, String)> = Vec::new();
for cap in re.captures_iter(&protected) {
    if let Some(m) = cap.get(0) {
        to_remove.push((m.start(), m.end(), m.as_str().to_string()));
    }
}
let mut stripped = protected;
for (start, end, text) in to_remove.iter().rev() {
    stripped = format!("{}{}",
        safe_slice(&stripped, 0, *start),
        safe_slice(&stripped, *end, stripped.len())
    );
}
```

**问题**: `to_remove` 索引相对 `protected`, 但删除时基于 `stripped` (已经缩短). 倒序删除**只对位置不重叠的情况**有效.

举例 (`AAA[证据:B]CCC[证据:DDDD]EEE`):
- protected: `AAA[证据:B]CCC[证据:DDDD]EEE`
- to_remove: [(4, 14), (18, 28)]
- 倒序处理: 先 (18, 28) 再 (4, 14)
- 删 (18, 28): stripped = `AAA[证据:B]CCCEEE` (19 chars)
- 删 (4, 14): stripped[14..] = `B]CCCEEE` (索引 14 现在指向 `B` 不是 `E`) — **bug!**

实际结果: `AAA[B]CCCEEE` (残留了 `[` 和部分 `BBBB`), 没正确删除 `[证据:B]`.

LLM 输出 6+ 个非标 evidence ID 时, 几乎所有删除都索引错位, 导致一个 ID 都没正确删除.

## 修复 (v3: 改用 placeholder 替换 + 一次性拼接)

```rust
// 1. placeholder 替换 mm:ss (按出现顺序 push)
// 2. 在 protected 上逐个 non_std_re 找到, 用 stripped.push_str + safe_slice 拼接
//    (single pass, 不用多轮删除)
// 3. placeholder 替换回 mm:ss (按出现顺序)
```

不再用多轮 format! 删除, 改用单 pass push_str + safe_slice, 完全避开索引错位.
