## 真问题

之前以为前端 TranscriptView 没接 partial,实际 `TranscriptContext.tsx:24-25` 已有 `livePartialText` state,`TranscriptView.tsx:341-352` 已经在渲染灰色 preview,`transcriptService.onTranscriptPartial` 已经在监听 `transcript-partial` 事件。

**唯一缺口**:Rust 端 emit 的是 `streaming-partial`,**事件名不匹配**。

## 改动(只动 1 文件)

```
M  frontend/src-tauri/src/audio/transcription/worker.rs  (改事件名 + 补全字段)
```

### Step 1: 事件名对齐
```
streaming-partial       →  transcript-partial
streaming-session-started  →  transcript-session-started
streaming-session-ended    →  transcript-session-ended
```

### Step 2: 补全 transcript-partial payload 字段
**前端契约**(transcriptService.ts:67-87)要求:
- `text` (string) — 灰色预览文本
- `delta` (string) — final 段文本
- `is_endpoint` (bool) — 句末标记
- `chunk_id` (number) — chunk 序号
- `audio_start_time` (number) — 秒
- `audio_end_time` (number) — 秒
- 可选 `decode_ms` / `buffer_age_ms` — 诊断字段

**Rust 端修改后**:
```rust
app.emit("transcript-partial", &serde_json::json!({
    "chunk_id": chunk_id,
    "text": streamed.partial,
    "delta": streamed.delta,
    "is_endpoint": streamed.is_endpoint,
    "is_partial": true,
    "audio_start_time": chunk_timestamp,
    "audio_end_time": chunk_timestamp + chunk_duration,
}))
```

### Step 3: 函数顶部提前抓 chunk_timestamp/chunk_duration
避免 `chunk.data` 被 move 后无法访问。

### 开 flag 模式
```bash

```
- 每个 chunk(1-2s 音频)结束 → daemon 返 partial
- Rust emit `transcript-partial` 事件
- `TranscriptContext.onTranscriptPartial` 收到 → `setLivePartialText(text)`

- 400ms 后 partial 清空,等 `transcript-update` 事件 + `transcriptService.onTranscriptUpdate` 把 final 段塞进 transcripts 列表
- 黑色 final 段出现,灰色 partial 消失,**无缝过渡无闪烁**
