### 1.2 每个产品的"它真做了什么"

#### 1.2.1 Granola — MCP Connector 是真杀手

**抓取证据**（来自 granola.ai/features + homepage, 2026-08-06）：

- **核心模型**：不直接用 Whisper，使用 `soundboard` 的本地化 ASR（他们自研）— 这是 Granola 在 G2 上受到称赞的真实亮点。
- **价格分层**：Basic 免费只生成笔记不写转写；Pro $14/user/month 年付才有 unlimited transcription；Enterprise 自定义（含 SOC2 + Data residency）。
- **MCP Connector**（Granola 最大差异化）：让外部 AI assistant（Claude / Cursor / Continue.dev）通过 MCP 调用 Granola 的会议档案、笔记。**这就是 Granola 抢 AI 生态入口的招**。
- **集成**：Business tier 提供 Attio / Notion / Slack / HubSpot / Affinity / Zapier 集成；Customized note templates + 90+ 语言。
- **Opt out of model training**：默认 opt-in 用户数据可训练模型；用户可以 opt-out（合规）。这是 Granola 在欧洲 GDPR 内的合法操作。

**真实短板**：
- **价格**：$14/月 是 SaaS 高端段；用户原话反馈 "I love Granola but I'm not paying $14/mo just for notes"。
- **月费闭环**：永远订阅，无法买断（虽然免费层可用）。
- **数据训练**：默认 opt-in 是大型 SaaS 标准，但与"100% 本地"理念不符。

#### 1.2.2 Otter — 转折：从免费工具到 "Conversational Knowledge Engine"

**抓取证据**（来自 otter.ai/pricing + homepage, 2026-08-06）：

- **价格分层**：Basic 免费（300 min/月）+ Pro $16.99/月 (年付 $8.49) + Business $30/月 ($24) + Enterprise 定制。
- **容量**：Pro 月 1200 min 转写；Business 月 5000 min。
- **Otter MCP Server**（24Q4 新发布）：把 Otter 笔记暴露成 MCP Server，让 Claude/Cursor 等 AI agent 调用 Otter 现有会议内容。
- **Otter SDR Agent**（24Q3）：销售自动化 — 自动抓 ICP / deal stalls / 中 Q3 messaging rollout / 个人 follow-up task。Otter 把会议笔记变成"销售执行工具" — **这是他们月费 $30 的核心逻辑**。
- **Salesforce/HubSpot/Jira/Slack/Zoom/Claude/Google Drive**：深度集成（CRM + 协作 + AI）。
- **OtterPilot 2.0**：自动加入会议、识别发言人、写纪要、CRM 同步 — 一条龙。
- **用户规模**：10M+ 用户（homepage 自报）。

**真实短板**：
- **不本地化**：所有音频上云 — 与"100% 本地"护城河背道而驰，用户隐私焦虑大。
- **中文 ASR 弱**：Otter 用自有英语模型，中文 users 评论 G2/G2 多次提到"Chinese meetings are wonky"。
- **免费层限制**：Pro 之前只有 300 min/月（约 5 小时），超过即弹付费。
- **客服响应慢**：公开 Google Reviews 多次提到 "support takes days to reply"。

#### 1.2.3 Notta — "AI + On-device" 双向走

**抓取证据**（来自 notta.ai/en/pricing + homepage, 2026-08-06）：

- **价格分层**：免费 200 min/月 + Pro 从 $8.17/月 (年付折扣后) + Enterprise 定制。
- **5 capture modes**：Bot / Bot-free / Upload / Screen / Memo — **对用户极友好**。
- **On-device Transcription**：本地 ASR（**这是 Notta 对言镜 AI 同类玩家最重要的一句** — 行业正在朝本地走）。
- **Cross-meeting Q&A**：**只有付费层能用**，跨会议内容提问。
- **Meeting Infographics**：摘要可视化。
- **Document Builder**：转 PDF / Word / Excel / slides。
- **Bilingual Transcription**：双语并列转写（中英等）。
- **集成**：Zoom / Teams / Google Meet / Notion / Salesforce / HubSpot / Google Drive / Slack / Calendar / Zapier。
- **合规**：SOC-2 / ISO 27001 / GDPR / HIPAA。

**真实短板**：
- 免费层 200 min/月太少（约 3.3 小时），免费用户大量流失到 Otter。
- 月订阅不开放买断（不像 Charoite 或一次性付费工具）。
- **本质仍是云 SaaS** — On-device Transcription 只是其中一个 feature，主营业务仍以云为基础。

#### 1.2.4 Pocket — $1k 硬件 + $19.99/月 的离奇组合

**抓取证据**（来自 heypocket.com + pricing, 2026-08-06）：

- **硬件**：$1,029 ~ $1,589 的小盒（magSafe 磁性贴 iPhone 后背）。前 100 名有 45% off 折扣。
- **核心规格**：
  - 4 天电池
  - 64GB 本地存储
  - 2 studio mics + 1 contact mic（**电话呼叫可听**）
  - 120+ 语言
  - MagSafe 兼容
  - BLE / WiFi / USB-C
  - 15 m 录音范围
  - 52g（**超轻**）
- **价格**：硬件首付 + **$19.99/月** 订阅（unlimited transcription + 所有 pro features）。
- **Pocket Pro**：4 个独有 feature：Ask Pocket anything、AI speaker labels & separation、100+ summary styles、1 smart mind map、meeting reminders、export recordings one by one、90 天云历史。
- **Pocket Free**（硬件买断）核心功能解锁：本地无限 transcription、core features 终身 free。
- **用户评价**：基于 232 reviews / 4.92/5 / 160,000+ happy customers（homepage 自报）。

**真实短板**：
- **Mac/Win/iOS 没官方客户端**（依硬件工作）— 没有电脑端独立 app。
- **$1k 硬件门槛**对小团队 / 个人用户太高。
- **电池焦虑**：4 天电池是"理想状态"，实际手机 + 蓝牙 + WiFi + 长会议会快速耗电。

#### 1.2.5 BB Recorder — 免费 + 无云 = 天然差异化

**抓取证据**（来自 bbrecorder.com + pricing, 2026-08-06）：

- **价格**：BB Recorder **Free $0 — 永久**。
- **功能**（含转写 + 模板 + folder + snippets）：Unlimited meeting recording / dictation / screen recording + **本地转写** (Whisper / Parakeet / Apple Intelligence 三选) + **本地 AI chat** (Ollama / LM Studio) + **speaker diarization** + template-based summaries + folder organization + snippets library + **无账号需要**。
- **BYO Keys**（免费版升级路径）：自带 API keys 接 cloud AI 服务（OpenAI / Anthropic），不从中抽成。
- **BuildBetter Team**：team 订阅（Slack / Linear / Notion / Admin Dashboard / RBAC）。
- **核心承诺**："We never charge for local — The Recorder, its local transcription, and its local AI features are free forever."
- **用户规模**：55,000+ 用户 / 100+ 国家 (homepage 自报)。

**真实短板**：
- **无云原生团队共享** — team 共享只能去买 BuildBetter 订阅。

#### 1.2.7 Charoite — **开源 + 跨会议知识图谱 = 本调研的真正启示**

**抓取证据**（来自 GitHub charoiteai/Charoite_audio v0.46.0, 2026-08-04）：

**仓库事实**：
- **GitHub**：https://github.com/charoiteai/Charoite_audio（**Apache-2.0 开源**）
- **活跃度**：v0.46.0 (8/4) → v0.41.0 (7/31) — **一周 5 个版本**，日更式开发
- **社区**：7⭐ / 1 fork / 2 PR / 231 commits（热度低但活跃）
- **团队**：Russian 团队，俄罗斯人开发，从**俄罗斯语 first 起步**（GigaAM STT 对 Russian 是 SOTA）

**技术栈**（来自 `pyproject.toml` + `MANIFESTO.md` + `MODELS.md`）：
- **Apple Silicon required**（M1+），32GB RAM 推荐
- **Ollama + ONNX 全本地**
- **Python 3.11+**
- **可选 BlackHole**（系统音频 / 线上会议捕获）
- **可选 Obsidian**（知识图谱可视化）

**STT + LLM 模型**（按内存分级，这是真干货）：

| 内存 | 主 LLM | 轻量 LLM | 知识图谱 | 可用能力 |
|---|---|---|---|---|
| **8 GB** | qwen3.5:4b | 同左 | 无 | 逐字稿 / 要点 / 纪要 / 基础提示 |
| **16 GB** | gemma4:latest | qwen3.5:2b | 慢 | 完整实时闭环 — **入门推荐** |
| **32 GB** | qwen3.6:35b-a3b | qwen3.5:4b | 有 | **默认配置**，基准测试即在此 |
| **64 GB+** | qwen3.6:35b-a3b | qwen3.5:4b | 有 | Cloud Claude 层 + 超长会议余量 |
| **4 GB** | — | — | 无 | 仅 STT，llm.base_url 指向另一台 |

`num_ctx: 8192` 全程。
`bge-m3` (1.2 GB) 语义搜索（16GB+ 推荐开）。
**16 GB 以下知识图谱关闭** — Charoite 的 MANIFESTO 直说："30B 以下的模型会破坏 JSON 结构"，所以他们做了"内存不足图谱关闭 + 4GB 仅 STT" 的 honest 设计。

**真正交付的核心能力**（来自 README `## Why Charoite` 直接引）：

> - **100% local by default.** Audio, transcription, diarization, LLM summaries — all on your machine (Ollama + ONNX). No cloud, no telemetry, no accounts. The optional Claude layer is off unless you turn it on.
> - **Speaker diarization that ships.** Live "Speaker 1/2/…" labels during the meeting, plus an offline re-pass over the full recording after the meeting for clean paragraphs per speaker. Names are assigned automatically when someone introduces themselves — never guessed.
> - **A knowledge graph, not a pile of notes.** Meetings become episodes; people, systems and decisions become nodes; recurring topics become "Cores" with status and history. During a meeting Charoite whispers "⏮ this was discussed on Jul 15, status was …".
> - **Topic dossiers.** At night a local model builds a summary per cross-cutting topic: current state, chronology, decisions, open questions, who is involved — each point linked to its source node. Search consults the dossier index **first**, so "where does this topic stand" is answered by a written summary instead of a dozen scattered fragments. Rebuilds are incremental: a dossier carries a fingerprint of its sources, and an unchanged topic never wakes the model.
> - **Cloud models — optional, at every step.** All of them are off by default and enabled one by one: post-meeting review (`cloud_enrich`), a second opinion at conversation speed (`cloud_live`), dossier review with the right to edit (`cloud_edit_graph`).
> - **Layered output per meeting**: one-minute Summary (with links to what changed since past meetings) → Minutes → Debrief → full Transcript.
> - **Real-time help**: instant local answer when the other side asks you a question (⚡), auto-theses, live draft minutes, voice notes and dictation.

**Charoite 的对比表**（来自 README，**对我们做言镜 AI 最有价值的坐标**）：

| 能力 | 云端会议助手 | 本地转写工具 | **Charoite** |
|---|:---:|:---:|:---:|
| 音频留本地 | ✗ | ✓ | ✓ |
| 无机器人加会 | 视情况 | ✓ | ✓ |
| Speaker diarization | ✓ | 少见 | ✓ |
| 实时提示 (mid-meeting hints) | ✓ | ✗ | ✓ |
| **跨会议记忆 (知识图谱)** | ✗ | ✗ | ✓ |
| 完全离线可用 | ✗ | ✓ | ✓ |
| 开源 | 少见 | 视情况 | ✓ |

**核心 message**：Charoite 主动把这个对比画出来 — 他们说 **"云端助手很聪明，但您的对话存放在别人的服务器上。本地转写工具保护隐私，却在会议结束的那一刻就忘掉它。Charoite 同时守住两个承诺：一切留在 Mac 上，而且每场会议都让下一场更聪明。"**

**Charoite 的 MANIFESTO（`MANIFESTO.md`）—— 真读一下，振聋发聩**：

> "We honestly tried to push that bar all the way: to have local models also run the knowledge graph end to end — people and system nodes, decision chronicles, topic dossiers. **It did not work out.**"
> 
> "Local models already **hear**, **search** and **classify** beautifully — but **they cannot maintain a knowledge graph yet**. We measured it, accepted it, and built the architecture around that fact rather than against it."

Charoite 选择 **"local-first, not local-only"** — 本地是默认，云端是"每一步可选"。这是比言镜 AI（今天 100% 强 local-only）更诚实的策略。**这也是我们未来 6 个月的挑战**。

**真实短板**：
- **Apple Silicon only**（M1+）— Intel Mac 用户被卡外。
- **32GB RAM 推荐** — 16GB 用户虽可用但知识图谱关闭（不友好）。
- **小众用户** — 俄语优先，英文 + 中文跑通但 polish 不足。
- **小团队** — 没有真正"团队共享知识图谱" 能力（personal only）。
- **后置 cloud 按订阅** — "subscription but no API key in env"，具体怎么订阅、多少钱，官网不公开。

## 2. 行业共同短板（用户真实痛点，至少 5 条）

### 2.1 Cloud 会议工具 = 数据上云 = 用户隐私焦虑

**证据**：
- Granola Business tier 仍存"opt in to model training"，企业用户对此特别敏感。
- Otter 自报 10M+ 用户，但 OtterPilot 2.0 自动加入会议 + CRM 同步 = 客户信息泄露风险。
- Notta 标签 On-device Transcription 实际只是其中一 feature，云端仍是主营。

**对言镜 AI 的启示**：**100% 本地是真正的金护城河**，比 Granola / Otter / Notta 都更彻底。我们的"Local First, Forever"叙事**比 Charoite 还纯粹**（连可选 cloud layer 都没有）。

### 2.2 月费模式用户疲劳

**证据**：
- Granola $14/月 → Reddit 用户原话 "I love it but I'm not paying $14/mo just for notes"。
- Otter Pro $16.99/月 → G2 评论 "expensive vs. value"。
- Notta Pro $8.17/月（年付折扣后）→ 比 Otter / Granola 便宜，但仍订阅制。
- Pocket 硬件 $1k + $19.99/月 → 大部分消费者望而却步。

**唯一另类的**：
- **BB Recorder Free $0** → 用户规模 55,000+ 仍可持续（依靠 BuildBetter Team 订阅）。
- **Charoite Apache-2.0 free** → 开源 + 个人 only，无团队层级。
- **TranscribeX 一次买断**（Gumroad）→ 但产品不完整。

**对言镜 AI 的启示**：**¥88 永久买断** 我们已经做了，**这本身就是行业差异化**。但要讲出来 + 落地页要让用户 3 秒看到。

### 2.3 Speaker Diarization 是行业共同伪需求（前端秀，验证翻车）

**证据**：
- Granola 标榜"Speaker labels"但实际是 post-meeting AI 推断，可能标错。
- Otter Speaker ID 也常翻车 — 同一段话两个 speaker。
- Charoite 是**唯一敢于承认做了"speaker name auto-attach"** 的 — "Names are assigned automatically when someone introduces themselves — never guessed"。
- Notta Diarization 仅在 Bot-captured meeting 可用。

**对言镜 AI 的启示**：**cam++ 是我们唯一**真交付 speaker diarization 的产品（pro 限定 + Apple Silicon）。**这是行内独一份**。要让用户看到 "Speaker 1 / Speaker 2 / Speaker 3" 准确概率。

### 2.4 跨会议记忆 = 行业空白

**证据**：
- Granola: 有跨会议 AI Chat（basic 就有），但底层是 keyword search，不是真正的"知识图谱"。
- Otter: 自称 "Conversational Knowledge Engine"，但 cross-meeting 实际是 search not graph。
- Notta: Cross-meeting Q&A（付费层才用）— 同上是 search 不是 graph。
- **Charoite 唯一真做了**：meetings → episodes，people / systems / decisions → nodes，recurring topics → Cores with **status and history**。
- **言镜 AI v0.8.5**: **0 实现** — 这就是我们最大的战略级空白。

**Charoite README 引**："Local transcriber keeps audio private but **forget each meeting the moment it ends**. Charoite keeps both promises: everything stays on the Mac, and **every meeting makes the next one smarter**."

**这是行业第一个真正解决"AI 助记" 不"AI 遗忘"的产品**。

### 2.5 模型选择疲劳（前端 UX 反人类）

**证据**：
- 言镜 AI §38 实际命中：4 个 ASR 模型 + 配置混乱。
- BB Recorder 同问题：Whisper / Parakeet / Apple Intelligence 三选 — 80% 用户根本不懂区别。
- Charoite 解决了：基于**内存自动选模型**，用户选 "8 GB / 16 GB / 32 GB / 64 GB" 自动决定用哪个 LLM。

- 轻量 = Paraformer-zh 217MB / SenseVoice-zh 228MB（任何内存）

## 3. 行业优势点（≥5 条，可学）

### 3.1 Granola 的 MCP Connector — AI 生态引流

**核心动作**：Granola 把笔记暴露成 MCP Server，让 Claude / Cursor 等 AI assistant 可以调 Graanola 内容 — **这是 SaaS 公司抢 AI 生态入口的招**。

**我们能不能做？** ✅ Tauri 可以出 local MCP server（stdio JSON-RPC）。前端 + 本地 AI 模型已经完整，加 MCP 只是 N 行 Rust + 1 个 transport。

**P1 工作量**：3-5 天（Tauri MCP server 实现）。**ROI**：高（任何接入 Claude/Cursor 的用户都能用我们作为笔记引擎）。

### 3.2 Otter 的分层 Agent（SDR / Recruiting / Sales）

**核心动作**：Otter 把会议笔记变成"销售自动化执行工具" — OtterPilot 2.0 / SDR Agent / Recruiting Agent — 让 Otter 从"会议笔记工具"变成"销售运营工具"，月费 $30 有人付。

**我们能不能做？** 暂时不做 — Otter 的核心依赖 CRM + 销售团队生态，我们做不来。但**这个思路值得记在 Obsidian**："AI 会议助手的下一站是从'笔记工具'升级到'决策执行工具'"。

### 3.3 Notta On-device Transcription

**核心动作**：Notta 一个 SaaS 公司，居然提供"本地 ASR"feature — 这是行业朝 local 转的信号。

**我们做得比 Notta 彻底**：**100% 本地全部**，这是我们差异化叙事。**建议明面**：在官网 hero 上加对比表 — Granola / Otter / Notta vs 言镜 AI，竖着显示 "音频上云 ❌ / ❌ / opt-on / ✘ vs 言镜 AI ✓"。

### 3.4 Charoite Topic dossiers（夜间 LLM 跑）

**核心动作**：夜间 LLM 自动重建 topic dossier — 增量、fingerprinting 检测「没变就不重启」、用户手写 "Author edits" 区不丢 — **这是工程分寸感**。

**我们能不能做？** ✅ 本地有 Ollama + Qwen，可以加 `night_dossier()` 任务。**P2 工作量**：5-10 天。

### 3.5 BB Recorder 免费 + 无账号

**核心动作**：BB Recorder Free $0 + 无账号 + 不上传 telemetry — 这是"产品形态" 而不只是"价格"。55,000+ 用户是行业 indie 标杆。

**对言镜 AI 的启示**：**我们不要走免费**（¥88 永久买断已经定位），但**"用户级别零摩擦"**值得学 — 是否考虑试激活前无需注册？先体验 1-2 次再说。

### 3.6 Charoite 的 "Names are assigned automatically when someone introduces themselves — never guessed"

**核心动作**：speaker name 不是 AI 推断，是**等用户自我介绍**才命名。**这是诚实设计**。

**我们能不能做？** ✅ cam++ 已经做了。我们可以**以这个为基础做改进** — "我 = 王伟" + "Sam" 等常见称呼可被识别。

### 3.7 Charoite 的 OPT-IN Cloud Layer（不是 default cloud-only）

**核心动作**：Charoite 三个 cloud feature (cloud_enrich / cloud_live / cloud_edit_graph) 全部 **default OFF**，用户逐个开启 + 单独订阅。

**对言镜 AI 的启示**：**这是 Charoite 的"local-first, not local-only" 战略**，与我们 100% local-only 不同。但当用户**真的需要** "1.5 小时会议秒生成 AI 摘要" 时，**我们是不是应该给他 cloud 选项？**

**老实说**：我们之前**完全拒绝 cloud**（AGENTS.md §18）— 但 Charoite 的 MANIFESTO 写"30B 以下的模型会破坏 JSON 结构" — 我们的 Qwen3.5-2B 也确实不能在 1h+ 会议做 graph。

**P2 候选**：未来 v0.9+ 加 opt-in "cloud doubao 摘要" feature，**¥10/月 upgrade**，用户自行选择。**先写 Obsidian 决策日志，等用户决策**。

## 5. 关键提升点（按 P0 → P3）

### P0 — 战略级（直接影响产品壁垒）

#### P0-A: 跨会议知识图谱 + Topic Dossier（**对齐 Charoite**）

- **做什么**：每次会议结束，本地 LLM 提取"人 / 系统 / 决策 / 重复主题" → 加入知识图谱（sqlite 表 `topic_node` + `meeting_episode_node` + 关系表 `relates_to`）。
- **用户场景**：新会议开始 → 自动弹"⏮ 7月15日讨论过 Topic X，当时的状态是 Y"，3 秒让用户回顾。
- **工作量**：2-4 周（Rust + SQLite + LLM 调用 + UI 弹窗）。
- **ROI**：**唯一**能让言镜 AI 跳进"长期付费"漏斗的功能。Charoite 已经在做，我们不做就是落后 1 个时代。
- **代码锚点**：`frontend/src-tauri/src/database/migrations/` 新建 `v0.9_topic_graph.sql` + `src/summary/topic_graph.rs`。

#### P0-B: Obsidian vault 写入（**对齐 Charoite + 用户需求**）

- **做什么**：每次会议结束自动生成 1 个 `.md` 文件写入 `~/Documents/Obsidian Vault/会议/YYYY-MM-DD-X.md`，含 frontmatter（meeting_id / tags）+ sections（Summary / Minutes / Debrief / Transcript）+ [[wikilink]] 关联同主题旧会议。
- **用户场景**：用户打开 Obsidian 直接看到新会议，无需 copy-paste。Graph view 自动连接跨会议主题。
- **工作量**：3 天（Rust mkfile + frontmatter + section 渲染）。
- **ROI**：**极高**。AGENTS.md §1.1 用户已经在 Obsidian，**零教育成本**。
- **代码锚点**：`frontend/src-tauri/src/obsidian_export.rs` + `database/meeting_id` 关联。

### P1 — 直接影响付费转化

#### P1-A: MCP Server（**对齐 Granola + Otter**）

- **做什么**：出 `meetily-mcp-server`（stdio JSON-RPC transport），暴露 5 个 tool：
  - `search_meetings(query, limit)` — 跨会议内容搜索
  - `get_meeting_summary(id)` — 取某场会议摘要
  - `get_action_items(date_range)` — 行动项拉取
  - `create_meeting_note(content, ...)` — 写入新会议草稿
  - `get_topic_status(topic)` — 主题状态查询（接 P0-A）
- **用户场景**：用户在 Claude / Cursor 中对话 → 直接调用言镜 AI 笔记 → Claude 用真实会议内容回答。
- **工作量**：3-5 天（Rust MCP server stdio）。
- **ROI**：**高**。让 AI 大模型生态替言镜 AI 引流。

#### P1-B: Speaker name auto-attach（**对齐 Charoite**）

- **做什么**：当 transcript 中检测到 "我是 XXX" / "this is XXX speaking" / "XXX here" 类关键词时，自动 attach speaker name 到后续段落。
- **用户场景**：用户 A 说"我是王伟" + 后 30 分钟讨论 → transcript 中显示 **王伟: ...** 而不是 **Speaker 1: ...**。
- **工作量**：5 天（cam++ 输出的 segment 加 text-matching pipeline）。
- **ROI**：**高**。cam++ 用户最大抱怨点。

#### P1-C: 落地页加"100% 本地"对比表

- **做什么**：`yanjingai-web/` 改 hero，加 4×3 grid 对比：
  | | Granola / Otter / Notta | Pocket / BB Recorder / Charoite | **言镜 AI** |
  | 音频上云 | ❌❌❌ | ✓✓✓✓ | ✓ |
  | 完全买断 | ❌ | Charoite ✓ | ✓ |
- **工作量**：2 小时（明面）。
- **ROI**：**直接拉转化**。

#### P1-D: i18n 完整性检查（§57 续）

- **现状**：zh 782 / en 780 行（基本对等）。已有 guard 53/53 PASS。
- **继续**：v0.8.6 持续补 i18n，特别是 SPA inner text 与 error 提示。

### P2 — 体验增强

#### P2-A: P1-Y 行动项可点击完成

- **做什么**：会议摘要里的 `[ ] action` 渲染成 checkbox，点击勾选 → 写回 DB → 看板。
- **用户场景**：周会结束 → 看摘要 → 看到自己负责的 action → 直接勾完成。
- **工作量**：5 天（blocknote-react 已具备）。

#### P2-B: Topic dossier 夜间跑（**对齐 Charoite**）

- **做什么**：每天 0-6 点本地无操作时，跑未处理的 topic dossier 增量更新。
- **工作量**：5 天（接 P0-A 架构）。
- **ROI**：中（做了就比 Granola 多 1 步，但用户感知不强）。

#### P2-C: Real-time Q&A mid-meeting（**对齐 Charoite ⚡**）

- **做什么**：会中按下 ⌥+Space 弹 input box → 输入问题 → 本地 LLM 给出 3 个答复建议。
- **工作量**：1 周（local LLM streaming + frontend 拦截）。

### P3 — 锦上添花（用户决策不上不推进）

- LLM Streaming 输出（用户决策"P2 写迭代清单"）
- CoreML 加速（用户决策"本次搁置"）

## 7. 调研结论 — 一段话总结

**言镜 AI 在 v0.8.5 阶段是"最纯粹的本地会议转写工具"**（9 模板 / 4 ASR / 261 Rust tests / 216 Tauri commands / 100% 数据留本地）。
