| **P1** | 民事案件摘要使用"公诉人" — 民事侵权案无公诉人 (刑事案用语) | 🟠 高 — 模板错配, LLM 串模板 |

## 修复策略 (P0 + P1 + P2 同时落地)

### §182 P0-1 数字一致性校验
**核心**: `check_number_consistency(transcript, summary)` — 在 LLM 输出后立即跑.

**实现位置**: `frontend/src-tauri/src/summary/hard_post_process.rs`

**架构**:
1. `NUMBER_TOKEN_RE` — 提取 "数字+单位" 词法 token (阿拉伯数字 + 元/万元/亿元; 中文数字 + 同单位)
2. `normalize_token()` — `100余万元 → 100万元` (末尾"余"挪到单位前)
3. `COMPENSATION_CATEGORIES` — 11 类民事赔偿明细分类关键词
4. 主函数比对 transcript vs summary:
   - `unexpected_numbers` — summary 中存在但 transcript 找不到的数字
   - `category_mismatches` — 摘要中"死亡赔偿金 730400 元"类似模式, 但 transcript 中同分类下查不到

**测试** (24 个 §182 单测):
- `section_182_check_consistency_catches_100w_hallucination` — 用户实际事故模拟
- `section_182_check_consistency_normal_summary` — 正常摘要不误报
- `section_182_extract_*` — 中文/阿拉伯数字均能抽取

### §182 P1-1 模板错配检测
**核心**: `detect_template_keyword_mismatch(summary, declared_template_type)`

- `CRIMINAL_KEYWORDS` 18 个 (公诉人/被告人/量刑/抗诉/刑事责任能力等)
- `CIVIL_KEYWORDS` 11 个 (死亡赔偿金/精神抚慰金/住院伙食补助费等)
- 民事模板输出含刑事关键词 → `criminal_hits_in_civil` 报警
- 刑事模板输出含民事关键词 → `civil_hits_in_criminal` 反向报警

**案例**: 民事侵权案件摘要含"公诉人" → 立即报警"民事模板出现刑事关键词 '公诉人'"

### §182 P1-2 待查明事项真伪过滤
**核心**: `filter_pending_items(transcript, pending_section)`

- 假待查 (实际是辩论数据):
  - 含"数字+单位" (如 3.6米) → 标"庭审争议数据, 不是待查"
  - 含法条编号 (如 第一千一百六十五条) → 标"已庭审查清"
- 真待查 (真正需要后续确认):
  - 含"是否" / "待核实" / "尚未确认" 等关键词

**案例**: "1. 收杆水钻3.6米 2. 是否属于限制刑事责任能力人" → 第一条归类假待查, 报警; 第二条保留

### §182 P2-1 时间线冲突检测
**核心**: `detect_timeline_conflict(transcript, summary)` — 检查:
- 年份顺序错置 (升序 vs 实际摘要顺序)
- 年龄/年份逻辑矛盾 (摘要含年龄 + 年份回溯, 提示人工核对)

**宽松实现**: 仅在 years_summary 顺序与排序不一致时报警. 用户的"2014 死亡 vs 2018 案发"实际上是不同段落, 当前实现不强制报错. 留给 §X 完整时间线逻辑校验.
