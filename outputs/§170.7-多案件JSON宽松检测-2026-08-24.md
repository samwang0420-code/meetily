# §170.7 多案件 JSON 宽松检测 + 正则 fallback (2026-08-24)

## 触发
用户连续截图反馈"故意杀人案庭审实录"会议,右侧摘要区显示 raw JSON 字符串 `[{ "case_index": 1, "defendant": "造不", "content": "# ..." }]`,顶部没有多案件橙色 banner。

## 根因
`§165 wrap_summary_as_multi_case_array` 用 `serde_json::to_string` 序列化 content 时,**真实换行符未 escape** 成 `\\n`。前端 `JSON.parse` 严格模式抛 `Bad control character in string literal`,`§170.6 catch` 静默 fall through,走 Priority 2 markdown 解析,把 `[{` 当普通字符渲染。

`§170.6 console.log` 暴露: `typeof data.markdown === 'string' true`, `startsWith [{ true`,但 JSON.parse 抛异常。

## 修复 (commit e580668)
`frontend/src/components/AISummary/BlockNoteSummaryView.tsx` Priority 1.5 改为 3 步降级:

1. **严格 JSON.parse** (干净数据)
2. **宽松 JSON 解析** — 替换转义符 + 用 `[\s\S]` 代替 `.`(兼容 ES2017 target)
3. **极宽松正则 fallback** — 新增 `extractCasesByRegex(md)`,匹配每个 `{ case_index }` 块,提取 `case_index / defendant / content / warning`

`scripts/check_historical_fixes.py`:
- 修 §170.6 → §170.7 文案同步
- 新增 `170_7_regex_fallback` 锚点
- guard 578 → **579/579 PASS**

## ES2017 target 约束
`frontend/tsconfig.json:3` 设 `target: "es2017"`,**不支持 s regex flag**,必须用 `[\s\S]` 代替 `.`。
