# §137.3 topic_graph 优先 BuiltInAI 路径 — 本机 Qwen3.5 2B 直接用 (2026-08-19)

**触发**: 用户 8/19 反馈"我们本地不是有模型吗, 为什么还要再下载" — 弹窗 "想跨会议追踪主题, 需要本地 AI 模型" 让用户去下载 Ollama, 但本机已装 `models/summary/Qwen3.5-2B-Q4_K_M.gguf` (BuiltInAI 路径的本地 LLM)。

**根因** (3 跳):
1. `topic_graph::trigger_after_summary` §121 决定只支持 Ollama, 注释明确 "BuiltInAI 强制要 app_data_dir, trigger 链路传 None → llm 永远 fail"
2. `preflight_ollama_async` 只 ping localhost:11434, BuiltInAI 路径根本不查
3. 用户本机已装 Qwen3.5-2B-Q4_K_M.gguf (1221 MB), 但 Ollama 服务没起 → preflight fail → 弹窗要求用户下载 Ollama
4. 用户困惑: "本机不是有模型吗, 为什么还要下载"

**修复** (1 文件, +30/-10):
- 新增 `builtin_ai_model_exists(app_data_dir: &Path) -> bool` helper: 检查 `app_data_dir/models/summary/*.gguf`
- `preflight_ollama_async()` → `preflight_llm_async(app: &AppHandle) -> Result<&'static str, String>`:
  - 第一步: 检查 BuiltInAI (本机 .gguf) → Ok("builtin_ai")
  - 第二步: 3s timeout ping Ollama → Ok("ollama")
  - 都失败 → Err(reason)
- `trigger_after_summary` 加 BuiltInAI 分支:
  - 检查本机 .gguf → 用 `LLMProvider::BuiltInAI` + `qwen3.5:2b` + `app_data_dir=Some(...)`
  - 否则 fallback Ollama (兼容)
- 调用方 `preflight_ollama_async()` → `preflight_llm_async(&app)` (2 处)

- 都没 → 弹窗 (兼容老逻辑)

**教训 (§56 强化)**:
1. **不要硬编码单一 provider** — BuiltInAI 跟 Ollama 是同等地位的本地 LLM 路径, 不应该只用 Ollama
2. **preflight 跟 trigger 必须支持同样 provider set** — §132 旧 preflight 只查 Ollama, 但 trigger 走 Ollama, 一致; §137.3 修复让 trigger 同时支持 BuiltInAI, preflight 也同步
3. **app_data_dir 是 Tauri 2 的标准 API** — `app.path().app_data_dir()`, 任何需要 sidecar binary 的路径都能用
4. **用户语 "本机有模型" = 任何已装的 LLM 模型** — 不是只 ASR 模型, 提示 ASR/LLM 区别
5. **弹窗最忌讳诱导下载** — 用户已装能用, 就直接用, 弹窗推荐"已装路径" 而不是"下载新东西"
