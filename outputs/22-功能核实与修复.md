# 离线会记功能核实与修复记录

日期：2026-07-16

## 结论

本轮没有继续堆功能，而是对已有功能链路做了可复现核查，并修复了 2 个真实缺口。

## 修复

1. **默认阻塞转录路径热词未生效**
   - 原因：`SherpaProvider` 调用 `transcribe_blocking` 时把 `hotwords_pack` 和 `hotwords_custom` 写死为空。
   - 修复：从全局热词配置读取，并将字符串安全地移动进阻塞任务。
   - 结果：不开启 streaming 时，热词仍然生效；streaming、默认转录、重转录使用同一份热词配置。

2. **垂直模板不一定进入应用 binary**
   - 原因：法律、医疗、跨境电商模板只依赖安装资源目录，开发态或资源目录未初始化时可能无法列出。
   - 修复：将 3 个模板通过 `include_str!` 编译期嵌入内置 registry；安装资源仍保留，便于未来扩展。
   - 结果：模板列表/加载不依赖外部模板目录，release binary 已验证包含三个模板标识。

3. **旧格式会议摘要导出兼容性**
   - 原因：legacy 摘要没有 markdown 字段时，导出按钮直接判定为空。
   - 修复：复用 legacy sections/blocks 转 Markdown 的 fallback；TXT 导出同时去除基础 Markdown 标记。

4. **摘要按钮组的中英文硬编码**
   - 修复：保存、复制、导出 MD/TXT 的按钮文案改用现有 i18n key，并补齐保存相关 key。

## 核验结果

- i18n 递归 key：`405` 个，中文/英文 `0` 差异。
- Rust 模板单元测试：`12 passed, 0 failed`。
- `cargo check`：通过，仅有已有 warning。
- `cargo build --release`：通过。
- 前端 `npm run build`：通过，15 个静态页面生成成功。
- release binary：`target/release/meetily` 约 63MB，`strings` 可找到 `legal_consultation`、`medical_consultation`、`cross_border_ecommerce`。

## 尚未声称通过的项目

- 真实 GUI 30 秒录音回归尚未由用户在当前 GUI 会话执行；按项目铁律，不能用 CLI 启动 binary 冒充这一步。
- 前端全量 `tsc --noEmit` 被仓库现有 `tests/lib/blocknote-markdown.test.ts` 的 `bun:test` 类型缺失阻断；Next 生产构建的类型检查已通过。
- 全仓库仍存在历史硬编码文案，但本轮只处理了摘要按钮组，避免无边界重构。
