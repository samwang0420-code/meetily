## 关键设计决策

### 1. feature flag 默认 false
```rust
pub fn streaming_enabled() -> bool {
    std::env::var("OFFLINE_HUIJI_STREAMING")
        .map(|v| v == "1" || v.to_lowercase() == "true")
        .unwrap_or(false)  // ← 默认 false
}
```
- **保守起见**:7/12 事故就是因为默认 streaming 路径 bug
- 开启需用户/管理员明确 `OFFLINE_HUIJI_STREAMING=true`

### 2. session 全局 Mutex(防 7/12 重蹈)
```rust
static SESSION_MAP: Lazy<Mutex<HashMap<String, SessionMeta>>> =
    Lazy::new(|| Mutex::new(HashMap::new()));
```
- 多 worker 不能各自建 session,会冲突
- 全局 map 唯一管理,异常退出可 `cleanup_all_sessions()`

### 3. 不动 worker.rs 主路径
- 第 497 行 Sherpa 分支仍是 `provider.transcribe_blocking`
- streaming 是"可选的备用路径",出问题不影响 blocking
- 这就是 §15 铁律第 1 步:**改 Rust 必须 cargo check + binary build + GUI 验证**,但**主路径没动**,所以 blocking 路径不退化

### 4. 失败回退设计
- streaming 任何错误(daemon 无响应 / 模型未下 / session 失效)→ 立即 fallback 到 transcribe_blocking
- 返回 `StreamChunkResult { error: "..." }`,调用方决定怎么处理
- 永不阻塞主流程
