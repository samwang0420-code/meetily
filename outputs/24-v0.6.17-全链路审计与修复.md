# 离线会记全链路审计与 v0.6.17 修复

日期：2026-07-16

## 审计范围

录音采集 → 实时转录 → 前端缓冲 → SQLite 保存 → 文件重转写 → 会议页加载 → 摘要生成。

## 发现的链路问题

1. 实时结果先被保存并展示，录音后重转写在后台异步启动；用户会把草稿误认为最终文本。
2. 重转写完成后，会议页没有统一监听完成事件，可能继续显示旧分页数据。
3. streaming finalize 的尾段时间戳固定为 `0.0`，会排序到录音开头并破坏音频回溯。
4. 摘要虽然增加了证据提示，但核心输入仍取决于转录质量；不能用提示词掩盖 ASR 错误。
5. 当前 Rust 停止流程把 SQLite 保存交给前端，存在窗口关闭/事件竞态导致的可靠性风险；本轮没有冒险重构会议 ID 和保存协议，留作下一阶段原子化改造。

## 本轮修复

- `frontend/src/app/meeting-details/page.tsx`
  - 监听 `retranscription-complete`。
  - 仅匹配当前会议时重新拉取 metadata 和 transcripts，最终重转写结果可见。

- `frontend/src-tauri/src/audio/transcription/worker.rs`
  - 记录本次录音最后一个音频结束位置。
  - streaming finalize 尾段不再使用 `0.0` 时间戳，而是落在最后音频位置附近。
  - 每次新录音重置该位置。

- `frontend/src-tauri/src/summary/processor.rs`
  - 保留并强化证据约束：只用原文事实、保留时间戳、提案/决定分离、不确定内容需确认。

- `npm run build`：通过，15 个页面生成成功。
- `cargo test summary::processor --lib`：21 passed, 0 failed。

## 下一阶段必须做

- 不再继续加模板或营销。
- 建立固定真实音频集，比较实时结果和录音后重转写结果。
- 测量漏字率、专名/数字错误率、行动项错误率、时间戳回溯准确率。
- 决定最终默认模型和音频前处理链。
- 之后再做停止流程的 Rust 原子保存，消除前端事件竞态。

## 诚实边界

本轮修复改善了数据流一致性和可回溯性，但没有证明 ASR 准确率已经达到商业化标准。没有真实音频基准前，不应宣称产品已可商用。
