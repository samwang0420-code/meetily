## commit 2facebc - Python diar DB 落库 (2 文件, 181 insertions)

### 算法
`_diar_apply_to_db(payload)`:

1. 拿 payload 字段: meeting_id, audio_start_offset_seconds, segments
2. 把 segments 转成 global 时间 (offset 加到 start/end)
3. SELECT 该 meeting 所有 `speaker IS NULL` 的 transcripts 行 (按 audio_start_time 排序)
4. 对每个 transcript 行, 找**最长 overlap** 的 segment
5. UPDATE 该行的 speaker = `speaker_NN` (格式 `speaker_00`, `speaker_01`, ...)
6. WHERE `id = ? AND speaker IS NULL` 保证幂等

为啥用 overlap 而不是范围 ±0.5s: 每个 diar segment 覆盖几秒, 每个 1s 一个 transcript 行, 一个 segment 命中 5 个 transcript 行. overlap 算法保证整段说话人一致, 不会因边界 miss 导致杂色标签.

### 配置
- DB path 读 `LIXIANHUIJI_DIAR_DB_PATH` 环境变量, 默认 `~/Library/Application Support/cn.lixianhuiji.app/meeting_minutes.sqlite`

### 持久化
`_persist_diar_result(rid, state, meeting_id, audio_start_offset)`:
- 先写 `/tmp/lixianhuiji_diar/<rid>.json` (含 meeting_id/audio_start_offset_seconds 字段)
- 当 meeting_id + offset 都在时, 同步调 `_diar_apply_to_db`, 写 stderr 报告 `updated=N reason=ok/error`

### 测试
- `test_diar_apply_to_db_with_real_meeting`: 用临时 SQLite DB (生产 schema), 插 8 行 transcripts (8/13/18/.../43s), 注入 `meeting_id='meeting-test'` + 2 segments, 验证 2 行命中 (overlap 算法: 第一条 transcript 8-13 与 seg 4-12 overlap, 第二条 13-18 与 seg 14-18 overlap), 其他保持 NULL
- `test_diar_apply_to_db_missing_meeting_id`: 无 meeting_id 时早返, 不碰 DB
