## 根因 (我 §109 误判)

§109 我**错误**认为:
- `TranscriptButtonGroup` (transcript 列工具栏) 跟 `SummaryUpdaterButtonGroup` (summary 列工具栏) 重复
- 用户说"页面乱"=两个工具栏重复

**实际正确理解**:
- **TranscriptButtonGroup**: transcript 列的专属工具 — **复制 transcript 文本 / 导出 transcript MD / 导出 transcript TXT / 打开录音文件夹 / 重新转录**
- **SummaryUpdaterButtonGroup**: summary 列的专属工具 — **保存 summary 修改 / 复制 summary / 导出 summary MD / 导出 summary TXT / 查找 / 打开文件夹**
- 两个工具栏功能**完全不同** (一个针对 transcript, 一个针对 summary), 不是重复
- 用户说"页面乱" = §104 之后 TranscriptButtonGroup 和 SummaryUpdaterButtonGroup 视觉上挤在一起 + summary 工具栏按钮较多 (5个) + Speaker Roster 加进来后 6 个按钮

§109 我把 TranscriptButtonGroup `{false && (...)}` 隐藏了, 用户**真正想要** transcript 列的 4 个按钮 (保存/复制/导出MD/导出TXT) **消失**了 → 反馈"现在都在一起了" = 都在 summary 列里, transcript 列空了

## 教训 (§56 强化)

§109 修复时我**没真正理解用户反馈**, 直接按"页面乱"字面意思理解成"两套工具栏重复"就隐藏了一个。

§56 铁律强化: 任何 §X 修复, **必须先确认用户真实意图** (尤其"页面乱"这种主观反馈), 不能想当然。
- "页面乱" 可能指: 重复 / 太挤 / 字号小 / 颜色冲突 / 缺某个按钮 / 顺序错乱 / 视觉权重不对
- **最小修改原则**: 不确定的, 问用户; 确定的, git revert 之前 commit, 而不是乱猜修复方向
