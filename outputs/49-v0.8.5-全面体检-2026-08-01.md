### 2.1 旧 §34 ASR 文本重复识别 (历史录音中)

**症状**: meeting-02c7f2d9 / a2851054 / 等会议的相邻段文本**几乎完全相同** (开头差几个字符)

**02c7f2d9 实际**:
```
s=27.48  "包吃住了,肯定包吃住了,不包吃住,你欠800个...南通江苏南通"
s=79.89  "三左右包吃住了,那肯定包吃住了,不包吃住你欠800个...南通江苏南通"
s=131.25 "10块钱5万13000左右,包吃住了,那肯定包吃住了,不包吃住,你欠800个..."
```

**根因**: §34 SpeechEnd.samples 在 8s 强切后又 emit 完整 utterance, 完整识别一次 + 8s 切段识别一次

**§34 在 import.rs 已有常量定义但未 enforcement**:
```rust
// 工作树里已存在:
const MAX_SEGMENT_OVERLAP_SECONDS: f64 = 0.05;
pub const MAX_REALTIME_SEGMENT_DURATION_SECONDS: f64 = 12.0;
pub const MAX_POST_SEGMENT_DURATION_SECONDS: f64 = 30.0;
```
但**只在文件末尾声明, 没在 save 路径上 check + reject**. 历史数据因此能绕过.

**修复**: 
- import.rs (重转录) + record path (实时录音) 都加 check
- 触发 reject 时 emit error 让前端展示

### 2.2 folder_path 50/51 缺失 (音频文件断链)

**症状**: `meetings.folder_path` 字段 50/51 行 NULL
- `~/Movies/meetily-recordings/` 实际有 73 个文件夹
- 但 DB 不知道, 重转录 API 找不到音频文件
- 这是 **DB 断链**, 不是音频文件丢失

**根因**: `api_save_transcript` 接收 `folder_path: Option<String>`, 当传 `None` 时**不 UPDATE**.

**前端流程**:
1. start_recording → placeholder meeting INSERT folder_path=NULL
2. 录音中: IndexedDB 存 folderPath
3. stop_recording → recording-stopped 事件 → frontend 存 sessionStorage
4. useRecordingStop → storageService.saveMeeting(folderPath=sessionStorage)
5. 后端 save_transcript → UPDATE folder_path (仅在 NULL 时)

**链路看似完整, 但 50/51 NULL 说明实际传输失败**. 可能原因:
- 早 binary 没这个兜底逻辑
- sessionStorage 被 clear (浏览器关闭)
- recording-stopped 事件触发失败

**修复**:
- 兜底 2: start_recording 时直接生成 folder_path 并 UPDATE (不靠 placeholder)
- 兜底 3: import path 不需要 folder_path, 音频文件可重新指认

## 4. audit_db.py 增强

新增 metric `asr_text_repeat` 检测文本完全重复段:
```sql
SELECT COUNT(*) AS dup_groups, SUM(c) AS dup_segs
FROM (SELECT transcript, COUNT(*) AS c FROM transcripts
      WHERE meeting_id=? AND LENGTH(transcript)>20
      GROUP BY transcript HAVING c>=2)
```
- 阈值: dup_segs >= 2
- 命中: a2851054 (1 pattern × 2 segs)
- 02c7f2d9 是相似但不精确重复, audit_db.py 难以文本相似度检测
